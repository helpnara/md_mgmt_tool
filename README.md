# 과제 이력 관리 도구

과제별 수행 이력을 마크다운으로 관리하는 웹 기반 도구.
파일·이미지 첨부를 이력과 같은 자리에 보관하고, 과제 단위로 진행 상황을 조회·검색·내보내기 한다.

- 데이터는 일반 `.md` 파일과 폴더로 저장된다 (Obsidian·VS Code 등에서 그대로 열림)
- 첨부는 과제 폴더 내 `assets/`에 상대경로로 저장 → 어떤 뷰어에서도 이미지가 보임
- SQLite는 검색·필터용 파생 인덱스이며 언제든 재생성 가능

---

## 사내 PC(윈도우)에서 테스트하기

Python 3.10 이상이 필요하다. ([python.org](https://www.python.org/downloads/) — 설치 화면에서
**“Add python.exe to PATH”** 를 반드시 체크할 것)

받는 방법은 둘 중 하나다.

* **GitHub에서** — 저장소의 `claude/team-task-management-tool-3d91g8` 브랜치에서
  `Code ▸ Download ZIP`
* **배포본 ZIP** — 필요한 파이썬 패키지를 `vendor/` 폴더에 함께 담은 압축본.
  사내망에서 외부 접속(PyPI)이 막혀 있어도 설치된다.

> **`vendor/` 는 파이썬 버전을 탄다.** 세 패키지(Pillow · pydantic-core · PyYAML)가
> 파이썬 버전마다 파일이 다르기 때문이다. 배포본 ZIP 이름에 적힌 버전과
> `python --version` 결과가 같아야 `setup.bat` 이 오프라인으로 설치된다.
> 다르면 아래처럼 그 버전용으로 다시 담으면 된다 (인터넷이 되는 PC에서).
>
> ```
> pip download --dest vendor --only-binary=:all: ^
>   --platform win_amd64 --python-version 3.14 --implementation cp ^
>   -r backend\requirements.txt
> ```
>
> `vendor/` 없이도 인터넷이 되는 PC라면 `setup.bat` 이 PyPI에서 바로 받아 설치한다.

압축을 푼 뒤 `setup.bat` → `run.bat` 순서로 더블클릭하면 된다.

## 윈도우에서 시작하기

Python 3.10 이상이 필요하다. ([python.org](https://www.python.org/downloads/) — 설치 화면에서
**“Add python.exe to PATH”** 를 반드시 체크할 것)

1. 이 저장소를 받아 압축을 푼다.
2. **`setup.bat`** 을 더블클릭한다 → 가상환경(`.venv`)을 만들고 필요한 패키지를 설치한다.
   인터넷이 막혀 있어도 `vendor/` 폴더가 함께 있으면 그것으로 설치한다
   (그 폴더가 이 PC의 파이썬 버전용이어야 한다 — 위 설명 참고).
   (배치 파일은 한글을 담지 않는다. 윈도우 cmd가 `.bat`을 cp949로 읽어
   UTF-8 한글이 들어가면 파싱이 깨지기 때문이며, 안내 문구는 `setup.py`가 출력한다.)
3. **`run.bat`** 을 더블클릭한다 → 브라우저가 열리고 도구가 뜬다.

두 번째 실행부터는 `run.bat` 만 누르면 된다. 종료는 검은 창에서 `Ctrl+C`.

```
run.bat                     기본 실행 (http://127.0.0.1:8000)
run.bat --port 9000         포트 변경
run.bat --vault D:\과제이력  데이터 폴더 위치 지정
```

> 화면 UI(`frontend/dist`)는 미리 빌드해 저장소에 포함해 두었으므로 **Node.js는 필요 없다.**
> UI 코드를 고칠 때만 `frontend`에서 `npm install && npm run build`가 필요하다.

### macOS / 리눅스

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
python3 run.py          # 또는 ./run.sh
```

## 데이터가 저장되는 모습

기본 위치는 이 폴더 아래 `vault/` 이며 `--vault` 로 바꿀 수 있다.

```
vault/projects/2026-001-리튬전지-장수명-셀-설계/
├── index.md                        과제 개요 + 메타데이터(front matter)
├── logs/
│   └── 2026-09-03-1차-수명-측정-결과.md
├── assets/
│   └── 2026-09-03/
│       ├── 001-측정그래프.png
│       └── 002-원시데이터.xlsx
└── reports/
    └── 2026-09-08/
        ├── report.md               보고 당시 문서 (확정 후 읽기 전용)
        └── assets/
            └── 001-주간보고.xlsx     보고에 사용한 원본 파일
```

`vault/` 폴더만 복사하면 그대로 백업이며, `.index/`(SQLite)는 지워도 실행 시 다시 만들어진다.
폴더를 직접 수정했다면 화면 우측 상단의 **[다시 읽기]** 를 누르면 반영된다.

## 지금까지 구현된 것

| 단계 | 내용 | 상태 |
|---|---|---|
| M0 | 실행 스크립트, vault 초기화, SQLite 스키마 | 완료 |
| M1 | 과제·진행일지 작성/수정, 파일 기반 저장, 재인덱싱 | 완료 |
| M2 | 이미지 붙여넣기·파일 첨부(진행률 표시), 자동 저장 토글 | 완료 |
| M3 | 상태 보드, 마감 필터, 통합 검색 | 완료 |
| M4 | 보고 이력 스냅샷, 엑셀 복사, 보고 대상 예측 | 완료 |
| M5 | 단일 md·HTML·zip 내보내기, 폴더 백업 | 완료 |
| M6 | 사내 서버 확장 (선택) | 미정 |

과제 목록 화면 맨 위에는 **대시보드**가 있다. 상태별·속성별·담당자별 과제 수, 이번 주 보고 대상 후보 5건,
마감 임박·기한 초과가 한 줄로 보인다. **모든 숫자는 눌린다** — 누르면 그 조건으로 목록이 걸러지고,
보고 대상을 누르면 그 과제 상세로 간다. 왼쪽 위 `▾ 과제 N건` 으로 접어 둘 수도 있다.


과제는 네 가지 축으로 관리한다.

| 축 | 값 | 성격 |
|---|---|---|
| **상태** | 예정 / 검토중 / 진행중 / 보류 / 완료 / 중단 | 진행 단계. 시간이 지나며 바뀐다 |
| **속성** | 스마트과제 / R&D / 투자 / 기획보고 / 국책과제 | 과제의 성격. 하나만 지정 |
| **그룹** | 자유 입력 (예: 차세대전지) | 묶어 보기 위한 분류 |
| **담당자** | 한 명부터 여러 명까지, 쉼표로 입력 | 담당자별 필터 제공 |

과제마다 **효과**를 적을 수 있다. 금액은 `기대효과` / `실증효과` 를 **억원/년** 단위로 나눠 적는다
(기대는 착수할 때, 실증은 끝난 뒤). 목록에 `1.2 → 1.4` 로 보이고 **효과 큰 순** 정렬이 된다.
숫자로 표현하기 어려운 정성적 효과와 금액의 산출 근거는 **과제 개요**에 적고,
근거 자료(엑셀·PPT)는 개요의 **[📎 파일 첨부]** 로 붙이거나 끌어다 놓으면 된다.

진행일지에 파일을 붙이는 방법은 세 가지다 — 이미지 **Ctrl+V**, 파일 **끌어다 놓기**, **[📎 파일 첨부] 버튼**.
**엑셀에서 표를 복사해 붙여넣으면 마크다운 표로 바뀐다.**

수행 이력에는 `── 여기까지 2026-08-25 보고함 ──` 선이 그어져, 목록만 봐도 미보고 분량이 보인다.
기록마다 **[이어쓰기]** 가 있어 지난 내용을 오늘 날짜로 가져와 쓸 수 있다.

지운 과제·기록·보고·첨부는 삭제되지 않고 **설정 → 삭제 보관함**에 남으며, 원래 자리로 되돌릴 수 있다.
**설정**에서 진행일지 서식(과제 속성별)과 보고 초안 서식도 바꿀 수 있다.

처음 실행하면 상단 **[설정]** 에서 **작성자**를 먼저 정해 두자. 이후 작성하는 진행일지와 보고에
누가 썼는지가 함께 기록된다. (나중에 여러 명이 함께 쓰게 되면 로그인한 사용자가 작성자가 된다)

## 주간 보고 흐름

1. **월요일** — 상단 [보고 대상] 에서 후보를 확인한다. 마지막 보고 후 경과일과 미보고 진행 건수로 정렬되며, 보고할 2–3건을 체크해 "이번 주 보고 묶음"에 담는다.
2. **월~화** — [보고 초안 만들기] 를 누르면 마지막 보고 이후의 진행일지만 모아 초안이 만들어진다. 다듬고, 보고에 쓴 엑셀을 끌어다 붙인다.
3. **화요일** — [엑셀 셀로 복사] 로 정리한 내용을 엑셀 한 칸에(줄바꿈 유지) 붙여넣어 보고한다. 보고를 마치면 [보고 확정] 을 누른다.
   확정된 문서는 읽기 전용 스냅샷으로 남고, 그 과제의 미보고 분량은 0으로 초기화된다.

## 새 버전으로 업데이트하기

새 배포본을 받았을 때:

1. 도구가 실행 중이면 검은 창에서 `Ctrl+C` 로 종료한다.
2. 새 압축을 **기존 폴더 위에 덮어쓴다.** 배포본에는 `vault` 폴더가 들어 있지 않으므로
   **작성한 데이터는 그대로 남는다.**
3. `setup.bat` 을 한 번 더 실행한다 (새로 추가된 패키지를 맞춰 준다).
   패키지가 그대로인 업데이트라면 이 단계는 건너뛰고 `run.bat` 만 눌러도 된다.
4. `run.bat` 으로 실행한다. 브라우저는 새로고침(Ctrl+F5).

> 화면만 바뀐 업데이트라면 `frontend/dist` 폴더만 덮어써도 된다.
> 화면 UI는 미리 빌드해 배포본에 담겨 있으므로 Node.js는 필요 없다.

걱정되면 2번 전에 `vault` 폴더만 다른 곳에 복사해 두면 완전한 백업이 된다.
