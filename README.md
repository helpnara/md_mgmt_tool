# 과제 이력 관리 도구

과제별 수행 이력을 마크다운으로 관리하는 웹 기반 도구.
파일·이미지 첨부를 이력과 같은 자리에 보관하고, 과제 단위로 진행 상황을 조회·검색·내보내기 한다.

- 데이터는 일반 `.md` 파일과 폴더로 저장된다 (Obsidian·VS Code 등에서 그대로 열림)
- 첨부는 과제 폴더 내 `assets/`에 상대경로로 저장 → 어떤 뷰어에서도 이미지가 보임
- SQLite는 검색·필터용 파생 인덱스이며 언제든 재생성 가능

## 사내 PC(윈도우)에서 테스트하기

Python 3.10 이상이 필요하다. ([python.org](https://www.python.org/downloads/) — 설치 화면에서
**“Add python.exe to PATH”** 를 반드시 체크할 것)

받는 방법은 둘 중 하나다.

* **GitHub에서** — 저장소의 `claude/team-task-management-tool-3d91g8` 브랜치에서
  `Code ▸ Download ZIP`
* **배포본 ZIP** — 필요한 파이썬 패키지를 `vendor/` 폴더에 함께 담은 압축본.
  사내망에서 외부 접속(PyPI)이 막혀 있어도 설치된다.

> **`vendor/` 는 파이썬 버전을 탄다.** 세 패키지(Pillow · pydantic-core · PyYAML)가
> 파이썬 버전마다 파일이 다르기 때문이다. 배포본 ZIP 이름에 적힌 버전과
> `python --version` 결과가 같아야 `setup.bat` 이 오프라인으로 설치된다.
> 다르면 아래처럼 그 버전용으로 다시 담으면 된다 (인터넷이 되는 PC에서).
>
> ```
> pip download --dest vendor --only-binary=:all: ^
>   --platform win_amd64 --python-version 3.14 --implementation cp ^
>   -r backend\requirements.txt
> ```
>
> `vendor/` 없이도 인터넷이 되는 PC라면 `setup.bat` 이 PyPI에서 바로 받아 설치한다.

압축을 푼 뒤 `setup.bat` → `run.bat` 순서로 더블클릭하면 된다.

## 윈도우에서 시작하기

Python 3.10 이상이 필요하다. ([python.org](https://www.python.org/downloads/) — 설치 화면에서
**“Add python.exe to PATH”** 를 반드시 체크할 것)

1. 이 저장소를 받아 압축을 푼다.
2. **`setup.bat`** 을 더블클릭한다 → 가상환경(`.venv`)을 만들고 필요한 패키지를 설치한다.
   인터넷이 막혀 있어도 `vendor/` 폴더가 함께 있으면 그것으로 설치한다
   (그 폴더가 이 PC의 파이썬 버전용이어야 한다 — 위 설명 참고).
   (배치 파일은 한글을 담지 않는다. 윈도우 cmd가 `.bat`을 cp949로 읽어
   UTF-8 한글이 들어가면 파싱이 깨지기 때문이며, 안내 문구는 `setup.py`가 출력한다.)
3. **`run.bat`** 을 더블클릭한다 → 브라우저가 열리고 도구가 뜬다.

두 번째 실행부터는 `run.bat` 만 누르면 된다. 종료는 검은 창에서 `Ctrl+C`.

```
run.bat                     기본 실행 (http://127.0.0.1:8000)
run.bat --port 9000         포트 변경
run.bat --vault D:\과제이력  데이터 폴더 위치 지정
```

> 화면 UI(`frontend/dist`)는 미리 빌드해 저장소에 포함해 두었으므로 **Node.js는 필요 없다.**
> UI 코드를 고칠 때만 `frontend`에서 `npm install && npm run build`가 필요하다.

### macOS / 리눅스

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
python3 run.py          # 또는 ./run.sh
```

## 데이터가 저장되는 모습

기본 위치는 이 폴더 아래 `vault/` 이며 `--vault` 로 바꿀 수 있다.

```
vault/projects/2026-001-리튬전지-장수명-셀-설계/
├── index.md                        과제 개요 + 메타데이터(front matter)
├── logs/
│   └── 2026-09-03-1차-수명-측정-결과.md
├── assets/
│   └── 2026-09-03/
│       ├── 001-측정그래프.png
│       └── 002-원시데이터.xlsx
└── reports/
    └── 2026-09-08/
        ├── report.md               보고 당시 문서 (확정 후 읽기 전용)
        └── assets/
            └── 001-주간보고.xlsx     보고에 사용한 원본 파일
```

`vault/` 폴더만 복사하면 그대로 백업이며, `.index/`(SQLite)는 지워도 실행 시 다시 만들어진다.
폴더를 직접 수정했다면 화면 우측 상단의 **[다시 읽기]** 를 누르면 반영된다.

처음 켜면 홈이 **무엇부터 하면 되는지** 알려 준다 — 작성자·담당자 명부를 정하고,
첫 과제를 만들고, 진행일지를 쓰는 세 걸음이다. 과제가 하나라도 생기면 그 자리에
아래의 현황판이 들어선다.

첫 화면은 **홈**이다. 연도를 하나 골라 그 해에 팀이 무엇을 했는지 본다 — 이번 주 할 일
(보고 대상·기한 초과·마감 임박·오래 방치된 과제), 팀 현황(과제·진행중·완료·보고 횟수·효과 금액),
연도별 추이, **팀원별 성과**·**속성별**·**그룹별**(셋 다 예정·검토중·진행중·보류·완료·중단 여섯 칸 + 효과 금액),
**이번 주 할 일과 팀 현황은 나란히** 서서 스크롤 없이 보인다.

**과제별 보고 표**(과제 × 1~12월. 칸에 보고일과 회의체가 찍히고 누르면 그 보고가 열린다)는
**[보고 이력]** 메뉴에 있다 — 줄이 과제 수만큼 늘어나기 때문이다.
여기서도 **모든 숫자는 눌린다** — 누르면 그 조건으로 걸러진 과제 목록으로 간다.

팀원별 표에는 그 해 **역량 이력 건수**가 함께 나온다. 과제 성과와 교육 이력을 한 줄에서
보면 면담 준비가 그 화면에서 끝난다 — 0이면 그 자체가 이야깃거리다.

> 홈의 수는 두 가지 기준을 함께 쓴다. 과제 수·완료·효과 금액은 **과제 번호의 연도**,
> 보고 횟수는 **보고한 날의 연도**로 센다. 화면에도 그렇게 적혀 있다.
> 팀원별 표는 **담당 중복 포함**이라 사람별 합이 팀 합계와 다를 수 있다.
> **효과 금액의 `기대 → 실증` 은 달성률이 아니다** — 실증은 끝난 과제에서만 나오므로,
> 몇 건에서 나온 값인지를 화면이 함께 적는다.

과제 목록 화면(**[과제]** 메뉴) 맨 위에는 **대시보드**가 있다. 상태별·속성별·담당자별 과제 수, 이번 주 보고 대상 후보 5건,
마감 임박·기한 초과가 한 줄로 보인다. **모든 숫자는 눌린다** — 누르면 그 조건으로 목록이 걸러지고,
보고 대상을 누르면 그 과제 상세로 간다. 왼쪽 위 `▾ 과제 N건` 으로 접어 둘 수도 있다.


**[팀원 역량]** 메뉴는 과제와 별개다. 교육·세미나·박람회·학회 참여 이력을 **사람 기준**으로 쌓는다.
한 교육에 여러 명이 갔으면 **누가** 칸에 쉼표로 이어 적으면 되고, 저장하면 **사람마다 한 건씩**
나뉘어 기록된다 (명부에서 이름을 눌러 넣을 수도 있다). 화면에서는 **같은 행사가 한 줄로 접혀**
보이고, 합계도 `행사 7건 · 참여 기록 11건` 처럼 둘을 나눠 적는다 — 사람 수만큼 세면
"올해 교육을 열한 번 보냈다"로 잘못 읽히기 때문이다. 고치거나 지우는 것은 사람마다 따로 한다. 2~3일에 걸친 교육은 **종료일**을 함께 적는다. 시간·비용은 **옵션**이라 비워 두어도 되고, 채운 것만 합계에 들어간다.
**지나간 이력만** 담는다 — 계획표가 아니라, 쌓인 이력을 놓고 *내년에 무엇을 하면 좋을지* 면담에서
이야기하기 위한 화면이다. 그래서 **그 해 기록이 없거나 오래 뜸한 사람**이 맨 위에 뜬다.
기록은 `vault/people/<이름>/activities/` 에 마크다운으로 쌓인다.

보고 문서에는 **[AI 요약 프롬프트 복사]** 가 있다. 이 도구는 **AI 를 부르지 않는다** — 보고 본문에
지시문을 붙여 **붙여넣기 좋은 글 한 덩이**를 만들어 줄 뿐이다. 사내에서 승인된 AI 도구에 붙여넣고
나온 요약을 옮겨 쓰면 된다. **나가는 것이 없으니 정책 승인이 필요 없다.**
앞뒤에 붙는 지시문은 **설정**에서 각자 쓰는 말로 바꿀 수 있다.

과제 정보에 **[별도 보고 불필요]** 를 체크하면 그 과제는 **보고 대상 후보에서 빠진다.**
단순 현황 관리를 과제로 세운 경우를 위한 것이며, 필요할 때 손으로 보고를 남기는 길은 그대로다.

과제는 네 가지 축으로 관리한다.

| 축 | 값 | 성격 |
|---|---|---|
| **상태** | 예정 / 검토중 / 진행중 / 보류 / 완료 / 중단 | 진행 단계. 시간이 지나며 바뀐다 |
| **속성** | 스마트과제 / R&D / 투자 / 기획보고 / 국책과제 | 과제의 성격. 하나만 지정 |
| **그룹** | 자유 입력 (예: 차세대전지) | 묶어 보기 위한 분류 |
| **담당자** | 한 명부터 여러 명까지, 쉼표로 입력 | 담당자별 필터 제공 |

과제마다 **효과**를 적을 수 있다. 금액은 `기대효과` / `실증효과` 를 **억원/년** 단위로 나눠 적는다
(기대는 착수할 때, 실증은 끝난 뒤). 목록에 `1.2 → 1.4` 로 보이고 **효과 큰 순** 정렬이 된다.
숫자로 표현하기 어려운 정성적 효과와 금액의 산출 근거는 **과제 개요**에 적고,
근거 자료(엑셀·PPT)는 개요의 **[📎 파일 첨부]** 로 붙이거나 끌어다 놓으면 된다.

진행일지에 파일을 붙이는 방법은 세 가지다 — 이미지 **Ctrl+V**, 파일 **끌어다 놓기**, **[📎 파일 첨부] 버튼**.
**엑셀에서 표를 복사해 붙여넣으면 마크다운 표로 바뀐다.**

보고 초안은 **보고일까지의 진행일지만** 담는다. 지난 이력을 몰아서 옮겨 넣을 때
(진행일지를 먼저 다 넣고 과거 보고를 날짜 지정해 만드는 경우) 첫 보고가 전부 삼키지 않게
하려는 것이다.

수행 이력에는 `── 여기까지 2026-08-25 보고함 ──` 선이 그어져, 목록만 봐도 미보고 분량이 보인다.
기록마다 **[이어쓰기]** 가 있어 지난 내용을 오늘 날짜로 가져와 쓸 수 있다.

안전망은 셋이다 — 문서를 저장할 때마다 **이전 내용이 `vault/.versions/` 에 남고**(설정에서 되돌린다),
설정한 주기마다 **vault 를 통째로 자동 백업**하며(백업 폴더는 vault 밖에 둔다), 오류가 나면
**설정 → 오류 기록**에 남는다. 오류 기록에는 **과제 내용이 담기지 않는다** — 언제·어디서·무슨 오류인지만
남긴다. 이 도구는 인터넷으로 아무것도 내보내지 않는다.

지운 과제·기록·보고·첨부는 삭제되지 않고 **설정 → 삭제 보관함**에 남으며, 원래 자리로 되돌릴 수 있다.
**설정**에서 진행일지 서식(과제 속성별)과 보고 초안 서식도 바꿀 수 있다.

**설정**에는 여러 사람이 쓰게 될 때를 위한 준비도 있다.
**담당자 명부**에 표준 이름을 모아 두면 자동완성이 그것을 쓰고, 명부에 없는 이름은
막지 않고 알려만 준다(누르면 바로 명부에 들어간다). 이미 쌓인 `권 경락` / `권경락` 같은
표기 흔들림은 **[다른 이름으로 통일]** 로 과제 파일까지 한 번에 바꾼다.
**과제 번호 체계**에 팀 코드를 넣으면 이후 만드는 과제가 `2026-소재-001` 이 된다
(이미 만든 번호는 바뀌지 않는다).

처음 실행하면 상단 **[설정]** 에서 **작성자**를 먼저 정해 두자. 이후 작성하는 진행일지와 보고에
누가 썼는지가 함께 기록된다. (나중에 여러 명이 함께 쓰게 되면 로그인한 사용자가 작성자가 된다)

보고하는 날 아침에는 상단에 **배너**가 뜹니다. 확정을 기다리는 초안이 **1건이면 그 초안으로
곧장**, 2~3건이면 과제 이름이 칩으로 서서 각각 그 초안으로 갑니다. 그보다 많으면
[보고 대상] 화면 맨 위의 *확정 대기* 목록으로 보냅니다. 오늘 보고를 다 마쳤다면
그날의 보고 이력으로 갑니다.

## 주간 보고 흐름

1. **월요일** — 상단 [보고 대상] 에서 후보를 확인한다. 마지막 보고 후 경과일과 미보고 진행 건수로 정렬되며, 보고할 2–3건을 체크해 "이번 주 보고 묶음"에 담는다. 묶음이 비어 있으면 그 자리에 무엇을 하면 되는지 안내가 뜬다.
2. **월~화** — [보고 초안 만들기] 를 누르면 마지막 보고 이후의 진행일지만 모아 초안이 만들어진다. 다듬고, 보고에 쓴 엑셀을 끌어다 붙인다.
3. **화요일** — [엑셀 셀로 복사] 로 정리한 내용을 엑셀 한 칸에(줄바꿈 유지) 붙여넣어 보고한다. 보고를 마치면 [보고 확정] 을 누른다.
   확정된 문서는 읽기 전용 스냅샷으로 남고, 그 과제의 미보고 분량은 0으로 초기화된다.

## 새 버전으로 업데이트하기

새 배포본을 받았을 때:

1. 도구가 실행 중이면 검은 창에서 `Ctrl+C` 로 종료한다.
2. 새 압축을 **기존 폴더 위에 덮어쓴다.** 배포본에는 `vault` 폴더가 들어 있지 않으므로
   **작성한 데이터는 그대로 남는다.**
3. `setup.bat` 을 한 번 더 실행한다 (새로 추가된 패키지를 맞춰 준다).
   패키지가 그대로인 업데이트라면 이 단계는 건너뛰고 `run.bat` 만 눌러도 된다.
4. `run.bat` 으로 실행한다. 브라우저는 새로고침(Ctrl+F5).

> 화면만 바뀐 업데이트라면 `frontend/dist` 폴더만 덮어써도 된다.
> 화면 UI는 미리 빌드해 배포본에 담겨 있으므로 Node.js는 필요 없다.

걱정되면 2번 전에 `vault` 폴더만 다른 곳에 복사해 두면 완전한 백업이 된다.

## 개발

```bash
.venv/bin/python -m pytest backend/tests -q     # 백엔드 테스트
node tests/ui/screens.mjs                       # 화면 테스트 (playwright 필요)
cd frontend && npm run dev                      # UI 개발 서버 (API는 8000번으로 프록시)
```

### 배포본 만들기

```bash
cd frontend && npm run build && cd ..     # 화면을 먼저 빌드한다
python tools/make_dist.py                 # dist/ 에 ZIP 이 생긴다 (파이썬 3.14 · win_amd64)
python tools/make_dist.py --python 3.13   # 사내 PC 의 파이썬이 다를 때
python tools/make_dist.py --no-vendor     # 인터넷이 되는 PC 용 (용량이 작다)
```

담기는 파일은 **git 이 추적하는 것**으로 정해진다(`git archive`). 그래서 `vault`·`.venv`·
`__pycache__` 가 딸려 갈 일이 없고, **커밋하지 않은 변경은 담기지 않는다.**
`vendor/` 는 이 명령을 실행하는 PC 에서 PyPI 로 내려받으므로 **빌드하는 쪽은 인터넷이 필요하다.**

**화면 테스트**는 주요 화면이 오류 없이 열리는지, 누른 결과가 약속과 맞는지
(대시보드의 수 = 목록이 거른 수), 그리고 **선택·마우스올림 상태까지 글자가 읽히는지**
(WCAG AA 명암비)를 본다. 화면을 픽셀 단위로 굳히지는 않는다 — 그러면 색 하나 바꿀 때마다
깨져서 아무도 안 돌리게 된다. 배포용 파일(`frontend/dist`)을 그대로 쓰므로
`npm run build` 를 먼저 해야 바뀐 화면이 시험된다.
