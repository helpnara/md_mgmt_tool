# 느린 나이테 — 과제 이력 관리 도구

과제별 수행 이력을 마크다운으로 관리하는 웹 기반 도구.
파일·이미지 첨부를 이력과 같은 자리에 보관하고, 과제 단위로 진행 상황을 조회·검색·내보내기 한다.

- 데이터는 일반 `.md` 파일과 폴더로 저장된다 (Obsidian·VS Code 등에서 그대로 열림)
- 첨부는 과제 폴더 내 `assets/`에 상대경로로 저장 → 어떤 뷰어에서도 이미지가 보임
- SQLite는 검색·필터용 파생 인덱스이며 언제든 재생성 가능

> **이름.** 나무는 한 해에 한 겹씩 굵어진다. 이 도구도 주 단위로 한 줄씩 쌓여야 비로소
> 그 해가 보인다 — *느린 부자의 기록 · 느린 여백* 과 같은 갈래의 이름이다 (2026-09-24 확정).
> 표시(아이콘)는 나무 단면이며, `frontend/public/favicon.svg` 하나가 원본이다.
> `favicon.ico`(16·32·48)는 윈도우 바로가기와 옛 브라우저용으로 같은 그림을 담았다.

## 사내 PC(윈도우)에서 테스트하기

Python 3.10 이상이 필요하다. ([python.org](https://www.python.org/downloads/) — 설치 화면에서
**“Add python.exe to PATH”** 를 반드시 체크할 것)

받는 방법은 둘 중 하나다.

* **GitHub에서** — 저장소의 `claude/team-task-management-tool-3d91g8` 브랜치에서
  `Code ▸ Download ZIP`
* **배포본 ZIP** — 필요한 파이썬 패키지를 `vendor/` 폴더에 함께 담은 압축본.
  사내망에서 외부 접속(PyPI)이 막혀 있어도 설치된다.

> **배포본 이름은 `느린나이테-20260924-v1.zip` 꼴이다** — 날짜와 그날의 판 번호다.
> 같은 날 두 번 만들면 `v2` 가 된다. 어느 파이썬용인지는 압축 안의
> `배포본-정보.txt` 에 적혀 있다.

> **`vendor/` 는 파이썬 버전을 탄다.** 세 패키지(Pillow · pydantic-core · PyYAML)가
> 파이썬 버전마다 파일이 다르기 때문이다. `배포본-정보.txt` 의 *대상 파이썬* 과
> `python --version` 결과가 같아야 `setup.bat` 이 오프라인으로 설치된다.
> 다르면 아래처럼 그 버전용으로 다시 담으면 된다 (인터넷이 되는 PC에서).
>
> ```
> pip download --dest vendor --only-binary=:all: ^
>   --platform win_amd64 --python-version 3.14 --implementation cp ^
>   -r backend\requirements.txt
> ```
>
> `vendor/` 없이도 인터넷이 되는 PC라면 `setup.bat` 이 PyPI에서 바로 받아 설치한다.

압축을 푼 뒤 `setup.bat` → `run.bat` 순서로 더블클릭하면 된다.

## 윈도우에서 시작하기

Python 3.10 이상이 필요하다. ([python.org](https://www.python.org/downloads/) — 설치 화면에서
**“Add python.exe to PATH”** 를 반드시 체크할 것)

1. 이 저장소를 받아 압축을 푼다.
2. **`setup.bat`** 을 더블클릭한다 → 가상환경(`.venv`)을 만들고 필요한 패키지를 설치한다.
   인터넷이 막혀 있어도 `vendor/` 폴더가 함께 있으면 그것으로 설치한다
   (그 폴더가 이 PC의 파이썬 버전용이어야 한다 — 위 설명 참고).
   (배치 파일은 한글을 담지 않는다. 윈도우 cmd가 `.bat`을 cp949로 읽어
   UTF-8 한글이 들어가면 파싱이 깨지기 때문이며, 안내 문구는 `setup.py`가 출력한다.)
3. **`run.bat`** 을 더블클릭한다 → 브라우저가 열리고 도구가 뜬다.

두 번째 실행부터는 `run.bat` 만 누르면 된다. 종료는 검은 창에서 `Ctrl+C`.
이미 켜져 있을 때 한 번 더 누르면 새로 켜지 않고 **브라우저만** 연다. 켜다가 오류가 나면 검은 창이
닫히지 않고 기다린다 — 그 글을 읽거나 찍어 두면 원인을 짚을 수 있다.

```
run.bat                     기본 실행 (http://127.0.0.1:8000)
run.bat --port 9000         포트 변경
run.bat --vault D:\과제이력  데이터 폴더 위치 지정
```

> 화면 UI(`frontend/dist`)는 미리 빌드해 저장소에 포함해 두었으므로 **Node.js는 필요 없다.**
> UI 코드를 고칠 때만 `frontend`에서 `npm install && npm run build`가 필요하다.

### macOS / 리눅스

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
python3 run.py          # 또는 ./run.sh
```

## 데이터가 저장되는 모습

기본 위치는 이 폴더 아래 `vault/` 이며 `--vault` 로 바꿀 수 있다.

```
vault/projects/2026-001-리튬전지-장수명-셀-설계/
├── index.md                        과제 개요 + 메타데이터(front matter)
├── logs/
│   └── 2026-09-03-1차-수명-측정-결과.md
├── assets/
│   └── 2026-09-03/
│       ├── 001-측정그래프.png
│       └── 002-원시데이터.xlsx
└── reports/
    └── 2026-09-08/
        ├── report.md               보고 당시 문서 (확정 후 읽기 전용)
        └── assets/
            └── 001-주간보고.xlsx     보고에 사용한 원본 파일
```

현업에게서 받은 과제 요청은 과제가 되기 전까지 `vault/intakes/` 에 따로 쌓인다(아래 *과제 접수 흐름*).

```
vault/intakes/R2026-001-압연-두께편차-예측/
├── request.md                      요청 내용 + 판정(front matter)
├── logs/                           인터뷰·검토 기록
└── assets/                         과제정의서.pptx · 부연 설명 원본
```

`vault/` 폴더만 복사하면 그대로 백업이며, `.index/`(SQLite)는 지워도 실행 시 다시 만들어진다.
폴더를 직접 수정했다면 화면 우측 상단의 **[다시 읽기]** 를 누르면 반영된다.

처음 켜면 홈이 **무엇부터 하면 되는지** 알려 준다 — 작성자·담당자 명부를 정하고,
첫 과제를 만들고, 진행일지를 쓰는 세 걸음이다. 과제가 하나라도 생기면 그 자리에
아래의 현황판이 들어선다.

첫 화면은 **홈**이다. 연도를 하나 골라 그 해에 팀이 무엇을 했는지 본다 — 이번 주 할 일
(보고 대상·기한 초과·마감 임박·**작성 중인 보고**·오래 방치된 과제), 팀 현황(과제·진행중·완료·보고 횟수·효과 금액),
연도별 추이, **팀원별 성과**·**속성별**·**그룹별**(셋 다 예정·검토중·진행중·보류·완료·중단 여섯 칸 + 효과 금액),
**이번 주 할 일과 팀 현황은 나란히** 서서 스크롤 없이 보인다.

**과제별 보고 표**(과제 × 1~12월. 칸에 보고일과 회의체가 찍히고 누르면 그 보고가 열린다)는
**[보고이력]** 메뉴에 있다 — 줄이 과제 수만큼 늘어나기 때문이다.
위에서 **기간**을 걸면 그 기간에 든 보고가 표에서 **붉게** 서고, 접힌 칸에서는 맨 앞으로
당겨지며, 그 열이 화면 밖이면 표가 가로로 밀려 온다 — 한 해치 칸 속에서 찾지 않아도 된다.
여기서도 **모든 숫자는 눌린다** — 누르면 그 조건으로 걸러진 과제 목록으로 간다.

팀원별 표에는 그 해 **역량 이력 건수**가 함께 나온다. 과제 성과와 교육 이력을 한 줄에서
보면 면담 준비가 그 화면에서 끝난다 — 0이면 그 자체가 이야깃거리다.

홈·과제목록·보고대상의 표에는 **[표 복사]** 가 있다. 지금 걸러진 줄을 그대로 탭 구분으로
클립보드에 넣어 주므로, **엑셀에 붙여넣으면 표가 된다.** "과제 현황 표 좀 보내 줘"에 화면을
보며 다시 치지 않아도 된다. 나가는 것은 클립보드뿐이다.

표마다 맨 아래에 **합계 줄**이 있다 — 지금 걸러진 줄만 더하고, 더할 수 없는 칸(이름·날짜·상태)은 `-` 다.
표 안의 0 도 `-` 로 선다. [표 복사] 에는 합계 줄이 들어가지 않고 0 은 0 으로 나간다(엑셀에서 다시 더할 수 있게).
과제목록에는 속성 옆에 **성격** 칸이 있다(스마트과제가 아니면 `-`).

자동 백업이 죽어 있으면(폴더에 닿지 않거나, 마지막 시도가 실패했거나, 마지막 성공이 주기의
두 배를 넘겼거나) 홈 맨 위에 한 줄이 뜬다. 정상이면 아무것도 뜨지 않는다.

> 거르기 상자는 **실제로 있는 것만** 세운다 — 과제가 한 건도 없는 해, 아무 과제에도 안 붙은
> 태그는 목록에 서지 않는다. 다만 상태·속성처럼 *고르는 말*은 그대로 둔다: "보류인 게 있나?" 에
> 없다고 답하는 것도 거르기의 쓸모다.

> 끝날 때까지 올해에도 보인다. 홈 · 과제목록 대시보드 · 과제목록 · 보고이력의 과제 × 월 표가 모두 같은 기준이다.
> **완료**는 그 해에 끝낸 과제(지난해를 고르면 그 뒤에 끝난 과제는 그 해에는 진행중 — 과제목록의 상태 칸 · 보드도 그 해의
> 상태로 보이고, 지금 상태가 다르면 옆에 `→ 2026-06-20 완료` 처럼 작게 적는다), **신규 착수**는 그 해에 시작한
> 과제(번호의 연도 — 과제목록의 [신규 착수만]), **효과 금액**은 기대 · 실증 모두 과제가 **끝나는 해**(완료년도, 아니면
> 마감년도)에만 센다 — 해마다 겹쳐 더하지 않고 그 해의 계획 대비 실적을 본다. 과제목록에서 다른 해에 세는 효과는
> 흐리게 보이고 합계 줄에 들지 않는다. 보고 횟수는 **보고한 날의 연도**로 센다.
> 기준 연도 옆에서 **상반기·하반기·분기**로도 볼 수 있는데, 보고 횟수·완료·역량 이력처럼 **날짜가 있는 숫자만** 그 기간을 따른다.
> 팀원별 표는 **담당 중복 포함**이라 사람별 합이 팀 합계와 다를 수 있다.
> **효과 금액의 `기대 → 실증` 은 달성률이 아니다** — 실증은 끝난 과제에서만 나오므로,
> 몇 건에서 나온 값인지를 화면이 함께 적는다.

과제 목록 화면(**[과제목록]** 메뉴) 맨 위에는 **대시보드**가 있다. 상태별·속성별·담당자별 과제 수, 이번 주 보고 대상 후보 5건,
마감 임박·기한 초과가 한 줄로 보인다. **모든 숫자는 눌린다** — 누르면 그 조건으로 목록이 걸러지고,
보고 대상을 누르면 그 과제 상세로 간다. 왼쪽 위 `▾ 과제 N건` 으로 접어 둘 수도 있다.


**[팀원역량]** 메뉴는 과제와 별개다. 교육·세미나·박람회·학회 참여 이력을 **사람 기준**으로 쌓는다.
한 교육에 여러 명이 갔으면 **누가** 칸에 쉼표로 이어 적으면 되고, 저장하면 **사람마다 한 건씩**
나뉘어 기록된다 (명부에서 이름을 눌러 넣을 수도 있다). 화면에서는 **같은 행사가 한 줄로 접혀**
보이고, 합계도 `행사 7건 · 참여 기록 11건` 처럼 둘을 나눠 적는다 — 사람 수만큼 세면
"올해 교육을 열한 번 보냈다"로 잘못 읽히기 때문이다. 고치거나 지우는 것은 사람마다 따로 한다. 2~3일에 걸친 교육은 **종료일**을 함께 적는다. 시간·비용은 **옵션**이라 비워 두어도 되고, 채운 것만 합계에 들어간다.
**지나간 이력만** 담는다 — 계획표가 아니라, 쌓인 이력을 놓고 *내년에 무엇을 하면 좋을지* 면담에서
이야기하기 위한 화면이다. 그래서 **그 해 기록이 없거나 오래 뜸한 사람**이 맨 위에 뜬다.
기록은 `vault/people/<이름>/activities/` 에 마크다운으로 쌓인다.

같은 화면에 **면담 기록**(TODO 182)이 있다. 사람을 고르고 **[면담 추가]** — 날짜 · 구분(정기 · 목표 설정 · 중간 점검 · 수시 ·
고충, 목록은 설정 → *팀원 면담*) · **한 줄 요약** · **하기로 한 것**(줄마다 하나) · 다음 면담일(선택) · 이야기한 내용. 하기로 한 것은
체크해 닫을 때까지 보이고, 사람을 고르지 않으면 **팀 전체의 아직 닫지 않은 것**이 모인다. 사람별 표에 *마지막 면담* · *하기로 한 것*
칸이 서고, 정한 다음 면담일이 지났거나 마지막 면담에서 주기(기본 90일)가 지난 사람은 **면담에서 먼저 볼 사람**에 함께 선다.
면담은 역량 이력 수에 세지 않는다. **민감한 기록이라 통합 검색 · AI 요약 · 내보내기에 들어가지 않고**, 파일은
`vault/people/<이름>/meetings/` 에 따로 쌓인다. 지워도 삭제 보관함 · 이전 버전에는 남는다(완전히 없애려면 보관함에서 비운다).
사람을 고르면 아래의 면담 기록 · 역량 기록만 그 사람으로 좁혀지고(위쪽 합계 · 표는 팀 전체 그대로), 그 두 칸 위에 띠가 선다 — **[팀 전체로 ×]**(또는 고른 이름을 한 번 더 누르기)로 돌아간다.

보고 문서에는 **[AI 요약 프롬프트 복사]** 가 있다. 이 도구는 **AI 를 부르지 않는다** — 보고 본문에
지시문을 붙여 **붙여넣기 좋은 글 한 덩이**를 만들어 줄 뿐이다. 사내에서 승인된 AI 도구에 붙여넣고
나온 요약을 옮겨 쓰면 된다. **나가는 것이 없으니 정책 승인이 필요 없다.**
앞뒤에 붙는 지시문은 **설정**에서 각자 쓰는 말로 바꿀 수 있다.

과제 정보에 **[별도 보고 불필요]** 를 체크하면 그 과제는 **보고 대상 후보에서 빠진다.**
단순 현황 관리를 과제로 세운 경우를 위한 것이며, 필요할 때 손으로 보고를 남기는 길은 그대로다.

그 위의 **[효과성 관리 비대상 과제]** 는 **금액으로 재지 않는 과제**를 위한 것이다. 유지보수처럼
효과 금액을 적지 않는 일이 홈의 *완료했는데 실증효과 미입력* 에 계속 남으면 그 숫자가 줄지 않고,
줄지 않는 경고는 곧 안 보게 된다. 체크하면 그 경고와 효과 금액의 분모에서 빠지고, 목록에
**[효과 비대상]** 딱지가 붙는다. 과제 자체는 그대로 관리된다.

홈의 효과 금액 아래 **기대 N건 · 실증 N건** 은 눌린다 — 누르면 그 금액이 적힌 과제만 나온다.

과제마다 **유관부서**를 적을 수 있다. 함께 일하는 팀과 그쪽 담당자다. 두 팀 이상이
협업하고 팀마다 담당자가 여럿인 경우를 그대로 담는다 — **한 줄이 팀 하나**이고,
담당자는 그 줄 안에서 쉼표로 적으면 저장할 때 **한 사람씩 나뉜다.**
담당자가 아직 정해지지 않았으면 팀만 적어 두어도 된다.

적어 두면 **팀 이름으로도 담당자 이름으로도 찾힌다** — 위쪽 검색창에서 "설비기술팀"이나
"김철수"로 검색하면 함께 일하는 과제가 나오고, 과제 목록의 **[유관부서]** 로 걸러 볼 수도
있다. 과제 상세의 유관부서 줄에서 팀이나 사람을 눌러도 같은 목록으로 간다.

과제는 네 가지 축으로 관리한다.

전배·퇴사로 팀을 떠난 사람은 **명부에서 지우지 말고 [떠난 날]을 적어 주세요.** 지우면 그 사람이
지난해 한 일이 &ldquo;명부에 없는 이름&rdquo;이 되어 오타와 뒤섞입니다. 날짜를 적으면 새 과제의
담당자 후보에서 빠지고, 이름 옆에 **[전배]·[퇴사]** 딱지가 붙으며, 아직 담당으로 남은 **끝나지 않은
과제**가 있으면 홈이 *대체 담당자 지정 필요* 로 알려 줍니다. 명부의 **[넘기기]** 를 누르면 그 과제들만
다른 사람에게 한 번에 넘어갑니다 — **끝난 과제는 그대로 둡니다.** 그때 그 사람이 한 것은 사실이니까요.

| 축 | 값 | 성격 |
|---|---|---|
| **상태** | 예정 / 검토중 / 진행중 / 보류 / 완료 / 중단 | 진행 단계. 시간이 지나며 바뀐다. 바뀔 때마다 진행일지에 `(상태) 진행중 → 보류` 한 줄이 남고, 완료가 되는 순간 **완료일**이 붙는다 |
| **속성** | 스마트과제 / R&D / 투자 / 기획보고 / 국책과제 / 유지보수 | 과제의 성격. 하나만 지정. **설정에서 더하고 빼고 고친다** |
| **그룹** | 자유 입력 (예: 차세대전지) | 묶어 보기 위한 분류 |
| **담당자** | 한 명부터 여러 명까지, 쉼표로 입력 | 담당자별 필터 제공 |

과제마다 **효과**를 적을 수 있다. 금액은 `기대효과` / `실증효과` 를 **억원/년** 단위로 나눠 적는다
(기대는 착수할 때, 실증은 끝난 뒤). 목록에 `1.2 → 1.4` 로 보이고 **효과 큰 순** 정렬이 된다.
입력은 소수 둘째 자리(100만 원)까지 받고, 화면에는 어디서나 **소수 첫째 자리**로 보인다(`1.25` → `1.3`, `3` → `3.0`).
숫자로 표현하기 어려운 정성적 효과와 금액의 산출 근거는 **과제 개요**에 적고,
근거 자료(엑셀·PPT)는 개요의 **[📎 파일 첨부]** 로 붙이거나 끌어다 놓으면 된다.

쓰다가 저장하지 않고 메뉴를 누르거나 새로고침하면 **"저장하지 않은 내용이 있습니다"** 를 묻는다.
과제 개요 · 보고 초안 · 접수 요청 내용 · 진행일지는 쓰던 글을 **데이터 폴더 안**(`.drafts/`, 이 PC 의 파일)에 임시로
남겨 두므로, 창을 그냥 닫았어도 — 다른 창 · 다른 브라우저로 열어도 — "작성 중 내용을 복구했습니다" 와 함께 돌아온다.
어디서 쓰다 말았는지는 홈 **이번 주 할 일**의 **작성 중이던 글**에 모이고, 그 카드에는 **작성 중** 표시가 붙는다.
본문 편집기는 모두 **Ctrl+S** 로 저장된다.
저장 · 삭제가 실패하면(파일을 엑셀로 열어 둔 채 지우기 등) 화면 아래에 **사유가 담긴 알림**이 뜬다.

탐색기 · 다른 편집기로 파일을 고치다 날짜를 잘못 적으면(`2026-02-30`) 그 **값만 비고** 과제는 그대로 보인다.
홈 · 과제목록 위에 **"읽지 못한 파일 · 값"** 이 떠서 어느 파일의 무엇인지 알려 준다 — 고친 뒤 [다시 읽기].

진행일지에 파일을 붙이는 방법은 세 가지다 — 이미지 **Ctrl+V**, 파일 **끌어다 놓기**, **[📎 파일 첨부] 버튼**.
보고·과제 개요·접수(요청 내용·검토 기록·새 접수 양식)도 같다.
**엑셀에서 표를 복사해 붙여넣으면 마크다운 표로 바뀐다** — 셀 안 줄바꿈과 병합 셀까지. 차트처럼 그림으로
넣고 싶으면 붙인 직후 편집기 아래에 뜨는 **[그림으로 바꾸기]** 를 누른다.

보고 초안은 **보고일까지의 진행일지만** 담는다. 지난 이력을 몰아서 옮겨 넣을 때
(진행일지를 먼저 다 넣고 과거 보고를 날짜 지정해 만드는 경우) 첫 보고가 전부 삼키지 않게
하려는 것이다.

수행 이력에는 `── 여기까지 2026-08-25 보고함 ──` 선이 그어져, 목록만 봐도 미보고 분량이 보인다.
요약 바의 **[미보고 N건]** 을 누르면 미보고 기록만 남는다.
기록마다 **[이어쓰기]** 가 있어 지난 내용을 오늘 날짜로 가져와 쓸 수 있다.
진행일지 서식의 `## 계획` 에 적은 것은 **다음 할 일**로 과제 위쪽 한 줄과 홈의 [이번 주 할 일]에
선다 — 표시만 한다. 체크박스도 마감도 없다.

확정된 보고 아래에는 **[보고 결과 · 지시사항]** 칸이 있다. 보고 자리에서 받은 지시를 거기 적어
두면 과제 위쪽에 *답하지 않은 지시 N건*으로 서고, **다음 보고 초안 맨 위에 자동으로 딸려
들어가며**, 답했으면 [답변함]으로 닫는다. 보고이력에서 *답하지 않은 지시만* 거를 수 있다.

해마다 도는 과제는 상세의 **[이 과제로 새 과제]** 로 만든다 — 원래 과제의 정보로 **미리 채운 새 과제 칸**이 열리고,
**[만들기]를 눌러야** 생긴다([취소]하면 아무것도 남지 않고 번호도 쓰지 않는다). 개요·담당자·유관부서·태그가
넘어오고 진행일지·보고·첨부는 넘어오지 않는다. 원래 과제가 새 과제의 **선행 과제**로 이어진다.

**다년도 과제**(1단계 · 2단계 · 3단계로 해마다 이어지는 과제)는 과제 정보 수정의 **선행 과제** 칸에 앞 단계의
과제 번호를 넣는다 — 목록에서 고르면 칩이 되고, 앞 단계 과제가 둘이면 둘 다 넣는다. 그러면 과제 머리 아래에
**단계 흐름**이 선다 — 단계마다 칸 하나(1단계 → 2단계 → 3단계), 같은 단계의 과제는 그 칸 안에 위아래로, 지금 보는
과제는 파란 테두리. 과제를 누르면 그리로 간다. 단계는 적지 않는다 — 선행을 따라 앞에서부터 세고,
뒤에 이어지는 과제가 있으면 그 바로 앞 단계로 당겨 선다(2년차에 **새로 시작해** 3년차로 합쳐지는 과제는 2단계). 번호를 다시 매겨도 선행 연결은 새 번호를 따라간다. 이어진 과제는 이름 뒤에 **N단계 띠**가 붙는다
(과제목록 · 보드 · 상세 · 보고대상 · 검색).

메뉴의 **[로드맵]** 은 이렇게 이어진 줄기를 모두 한 화면에 그린다 — 줄기마다 단계 수 · 기간 · 지금 단계 · 효과 합계,
과제마다 시작일 ~ 마감일 막대(색은 상태, 끝난 과제는 끝낸 날까지)에 **과제명**(막대가 짧으면 바로 옆에), 오늘 선.
단계마다 줄 바탕이 번갈아 칠해진다. 연결선은 평소에 그리지 않고, **막대에 마우스를 올리면** 그 과제의 앞 · 뒤 과제만 선으로
이어지고 나머지는 흐려진다. 왼쪽 칸은 단계 · 번호 · 상태 점, 한 단계에 과제가 여럿인 줄기는 "← 앞 과제 번호" 까지.
마감이 지났는데 끝나지 않은 과제는 막대 뒤에 붉은 빗금이 오늘까지 늘어난다. 맨 위 **살펴볼 것**에 늦은 과제 · 끊긴
선행 · 중단된 선행 위의 후속 · **올해 끝나는데 다음 단계가 없는 마지막 단계**가 모인다. 담당자 · 그룹 · 검색어 ·
보이는 기간으로 거르고, [표 복사]로 엑셀에 붙인다. 과제 상세의 줄기 띠 끝 **[로드맵에서 보기]** 는 그 줄기로 바로 간다.

메뉴 끝의 **[도움말]** 은 주간 보고 흐름·화면 지도·자주 묻는 것 세 쪽이다. 이 README 의
요약이며, 둘이 어긋나면 README 가 맞다.

안전망은 셋이다 — 문서를 저장할 때마다 **이전 내용이 `vault/.versions/` 에 남고**(설정에서 되돌린다),
설정한 주기마다 **vault 를 통째로 자동 백업**하며(백업 폴더는 vault 밖에 둔다 —
경로를 치지 않고 **[폴더 고르기]** 로 눌러서 정하고, 거기서 새 폴더도 만들 수 있다), 오류가 나면
**설정 → 오류 기록**에 남는다. 오류 기록에는 **과제 내용이 담기지 않는다** — 언제·어디서·무슨 오류인지만
남긴다. 이 도구는 인터넷으로 아무것도 내보내지 않는다.

자동 백업은 **층을 나눠 남깁니다** — 최근 **7일**치는 그대로, 그 앞은 **주마다 한 벌씩 4주**,
그 앞은 **달마다 한 벌씩 6개월**. 하루 한 벌씩 열 개만 남기면 되돌릴 수 있는 범위가 열흘뿐이라,
같은 개수로 훨씬 긴 기간을 덮기 위한 방식입니다(백업 업계에서 GFS 라고 부릅니다).
설정에서 층별 개수를 바꿀 수 있고, 카드 맨 위에 **어느 날짜까지 되돌릴 수 있는지**가 적힙니다.
같은 날 여러 번 백업하면 그날 마지막 한 벌만 남습니다.

지운 과제·기록·보고·첨부는 삭제되지 않고 **설정 → 삭제 보관함**에 남으며, 원래 자리로 되돌릴 수 있다.
**설정**에서 진행일지 서식(과제 속성별)과 보고 초안 서식도 바꿀 수 있다.

설정 화면은 하는 일이 같은 것끼리 다섯 묶음으로 서 있다 —
**기본**(작성자·담당자 명부·과제 번호 체계) · **보고**(요일·기준) · **서식**(진행일지·보고·AI 프롬프트) ·
**보관과 백업**(데이터 위치·전체 백업·자동 백업·이전 버전·삭제 보관함) · **점검**(최근 오류·첨부 링크 정리).

첨부 이름에 **공백이나 괄호**가 있으면 본문에 넣는 링크가 `<…>` 로 감싸져 끊기지 않는다.
예전에 넣어 둔 링크가 깨져 있다면 **설정 → 점검 → [첨부 링크 정리]** 에서 먼저 세어 보고 한 번에
고친다. 확정된 보고는 기본으로 두고, 체크하면 함께 고친다.

**설정**에는 여러 사람이 쓰게 될 때를 위한 준비도 있다.
**담당자 명부**는 이름·사번·담당 과제 수·떠난 날 네 칸이다.
표준 이름을 모아 두면 자동완성이 그것을 쓰고, 명부에 없는 이름은
막지 않고 알려만 준다(누르면 바로 명부에 들어간다). 이미 쌓인 `권 경락` / `권경락` 같은
표기 흔들림은 **[다른 이름으로 통일]** 로 과제 파일까지 한 번에 바꾼다.
**과제 속성**은 설정에서 팀이 쓰는 말로 **더하고 빼고 고칠 수 있다.**
이름을 고쳐도 **이미 만든 과제는 속성을 잃지 않는다** — 과제 파일에 남는 것은 이름이 아니라
속성 자체이기 때문이다. 쓰고 있는 속성은 뺄 수 없고(몇 건이 쓰는지 줄마다 보인다),
순서를 바꾸면 거르기 상자·대시보드가 그 순서를 따른다.

**과제 번호 체계**에 팀 코드를 넣으면 이후 만드는 과제가 `2026-소재-001` 이 된다
(이미 만든 번호는 바뀌지 않는다 — [과제 번호 일괄 변경]으로 한 번에 맞출 수 있다).

**과제 번호의 연도는 착수년도**다. 지난해에 한 과제를 올해 뒤늦게 등록하더라도 시작일을
`2025-01-01` 로 적으면 번호는 `2025-소재-001` 이 된다 — 홈의 **신규 착수**가 이 번호로 센다
(연도 거르기 자체는 수행기간이다). 시작일을 비우면 올해로 붙는다. 과제 만들기 화면은
저장하기 전에 **붙을 번호를 그대로 보여 준다.**
시작일을 나중에 고쳐 번호의 연도와 어긋나면 과제 상세 위쪽이 그 사실을 알려 주고,
누르면 그 해의 다음 번호로 옮겨 준다(폴더·진행일지·보고·이전 버전이 함께 따라온다).
자동으로 바뀌지는 않는다 — 번호는 이미 보고 자리에서 불린 이름이다.

처음 실행하면 상단 **[설정]** 에서 **작성자**를 먼저 정해 두자. 이후 작성하는 진행일지와 보고에
누가 썼는지가 함께 기록된다. (나중에 여러 명이 함께 쓰게 되면 로그인한 사용자가 작성자가 된다)

보고하는 날 아침에는 상단에 **배너**가 뜹니다. 확정을 기다리는 초안이 **1건이면 그 초안으로
곧장**, 2~3건이면 과제 이름이 칩으로 서서 각각 그 초안으로 갑니다. 그보다 많으면
[보고대상] 화면 맨 위의 *확정 대기* 목록으로 보냅니다. 오늘 보고를 다 마쳤다면
그날의 보고 이력으로 갑니다 — 그 화면의 과제별 보고 표에서 **오늘 보고한 것이 붉게** 섭니다.

쓰다가 **확정하지 않은 보고**는 홈의 [이번 주 할 일]에 계속 남습니다. 확정해야 보고 이력에
남고 그 진행일지가 미보고에서 빠지므로, 끝내지 않은 일로 봅니다. 보고일이 이미 지난 것은
붉게 `D+n` 이 붙고, 줄을 누르면 **그 초안 편집기로 곧장** 갑니다. 연도 조건을 따르지 않습니다 —
지난해 과제에 쓰다 만 보고가 있어도 그것은 오늘 마저 해야 할 일이기 때문입니다.

## 주간 보고 흐름

1. **월요일** — 상단 [보고대상] 에서 후보를 확인한다. 마지막 보고 후 경과일과 미보고 진행 건수로 정렬되며, 보고할 2–3건을 체크해 "이번 주 보고 묶음"에 담는다. 묶음이 비어 있으면 그 자리에 무엇을 하면 되는지 안내가 뜬다.
2. **월~화** — [보고 초안 만들기] 를 누르면 마지막 보고 이후의 진행일지만 모아 초안이 만들어진다. 다듬고, 보고에 쓴 엑셀을 끌어다 붙인다.
3. **화요일** — [엑셀 셀로 복사] 로 정리한 내용을 엑셀 한 칸에(줄바꿈 유지) 붙여넣어 보고한다. 보고를 마치면 [보고 확정] 을 누른다.
   확정된 문서는 읽기 전용 스냅샷으로 남고, 그 과제의 미보고 분량은 0으로 초기화된다.
4. **보고 뒤** — 회의에서 받은 지시는 확정된 보고의 [보고 결과 · 지시사항] 칸에 적어 둔다. 다음 초안이 그것을 맨 위에 물고 나오고, 답했으면 [답변함].

## 과제 접수 흐름

현업이 보낸 과제 요청이 과제가 되기까지 (TODO 136).

1. **접수** — 상단 [접수] → **[접수 등록]**. 받은 과제정의서의 내용을 접수 서식(배경 · 목표(성과지표) ·
   효과 산출 근거 · 추진내용 · 활용 방안 및 향후 계획)에 옮기고, 원본 파워포인트·부연 설명은 첨부로
   끌어다 붙인다. 번호는 `R2026-팀코드-001` 처럼 **과제와 따로** 붙는다(연도는 접수일).
2. **검토** — 인터뷰할 때마다 **검토 기록**을 남긴다. 문제 정의가 바뀌면 요청 내용을 고친다.
   받을 만한 건은 **★ 착수 후보**로 골라 둔다 — 풀에서 ★ 만 걸러 연간 계획 자료로 쓴다.
   **사전점검 체크리스트** — 접수 상세 요약 줄의 **[체크리스트]** 에서 다섯 분류 · 열 항목(필요성 · 수익성 ·
   구체성 · 데이터 · 기술성)을 단계별로 매긴다. 다 매기면 100점 만점 합계와 구간(80 이상 착수 권장 · 60 이상
   보완 필요 · 그 아래 보류 검토)이 서고, 풀에서 *사전점검* 열로 정렬해 착수 후보를 고른다. 바꿔 매길 때마다
   검토 기록에 한 줄이 남는다. 항목과 기준은 설정 → *과제 분류 · 접수* 에서 고친다.
3. **판정** — 보류·반려·이관은 **사유를 적어야** 정리된다. 이미 하는 과제와 같은 요청이면 **병합**으로
   그 과제에 잇는다. 판정은 검토 기록에 남고, **[재검토 (풀로 되돌리기)]** 로 되돌릴 수 있다.
   접수 후 14일(설정에서 바꾼다) 판정이 없으면 풀과 홈에 붉게 선다.
   접수 상세는 **2단**이다 — 왼쪽에 요청 내용·첨부, 오른쪽에 검토 기록. 요청 내용이 바뀌어 온 과정은
   **[이전 버전]** 에서 본다(되돌리는 것은 **본문**이고, 제목·상태 같은 정보는 지금 것 그대로다). 반려·이관된 것까지
   상단 **검색창**으로 찾는다.
4. **착수(승격)** — **[착수 · 과제로 승격]**. 미리 채운 대화상자를 확인하고 고친 뒤 만든다.
   * 과제리더가 **담당자 명부에 있으면 담당자**, 없으면(현업) **유관부서**로 들어간다.
   * 같은 이름의 섹션은 과제 개요의 같은 자리로, 나머지는 `## 접수 내용` 으로 옮겨진다.
   * 첨부는 과제로 **복사**된다(접수 쪽 원본도 남는다).
   * 요청자가 적은 기대효과는 **참고로만** 보인다 — 과제의 기대효과는 검토한 값을 적는다.
   * 과제와 접수 건에 서로 링크가 남는다.
   * 착수한 과제를 **삭제**하면 그 접수는 검토중으로 풀에 돌아간다(검토 기록에 한 줄). 하다가 그만둔
     과제라면 삭제보다 상태를 **중단**으로 두는 편이 맞다 — [삭제]를 누르면 그렇게 권한다. 삭제 보관함에서
     과제를 되돌리면, 접수가 아직 풀에 있을 때만 다시 이어진다.

스마트과제에는 **성격 · 분류 · 수행 방식 · 비용구분** 네 칸이 생겼다(목록은 설정 → *과제 분류 · 접수*).
홈에는 접수 풀 칸과 성격별·분류별 표, 효과 금액의 비용구분별 나눔이 선다.
급한 건은 접수를 거치지 않고 과제목록에서 바로 만들어도 된다. 그렇게 만든 스마트과제를 나중에 풀에서 다른
접수 건과 함께 고르고 싶으면 과제 상세의 **[접수로 되돌리기]** — 개요는 요청 내용으로, 진행일지는 검토 기록으로,
첨부는 복사되어 **검토중** 접수가 되고(접수일은 과제를 처음 만든 날), 과제는 삭제 보관함으로 간다. 그 과제 번호는
다시 쓰지 않는다. 보고가 있는 과제와 접수에서 승격된 과제(→ 접수 화면의 [재검토])는 되돌리지 않는다.

## 새 버전으로 업데이트하기

새 배포본을 받았을 때:

1. 도구가 실행 중이면 검은 창에서 `Ctrl+C` 로 종료한다. **켜 둔 채 덮어쓰면 옛 코드가 계속 돈다.**
2. 새 압축을 **기존 폴더 위에 덮어쓴다.** 배포본에는 `vault` 폴더가 들어 있지 않으므로
   **작성한 데이터는 그대로 남는다.**
   압축 안에는 `느린나이테\` 폴더가 한 겹 있다. 기존 폴더 이름이 `느린나이테` 라면
   **그 폴더의 상위 폴더**에서 풀어야 겹쳐진다 — 기존 폴더 *안에서* 풀면 `느린나이테\느린나이테\`
   가 생기고 아무것도 바뀌지 않는다.
3. `setup.bat` 을 한 번 더 실행한다 (새로 추가된 패키지를 맞춰 준다).
   패키지가 그대로인 업데이트라면 이 단계는 건너뛰고 `run.bat` 만 눌러도 된다.
   윈도우라면 이때 **바탕화면에 [느린 나이테] 바로가기**가 만들어진다(이미 있으면 새로 맞춘다).
   파워셸이 막힌 PC 에서는 조용히 넘어가므로, 배포본 맨 위의 `느린나이테.ico` 로
   손수 만들면 된다 — 바로가기 [속성 → 아이콘 변경] 에서 그 파일을 고른다.
4. `run.bat` 으로 실행한다. 브라우저는 새로고침(Ctrl+F5).
5. **설정 → 점검** 맨 위의 *지금 실행 중인 배포본* 이 새 이름(예: `느린나이테-20260924-v1`)인지
   본다. 옛 이름이면 2번(어느 폴더에 풀었나)이나 1번(껐다 켰나)이 빠진 것이다.

> 화면만 바뀐 업데이트라면 `frontend/dist` 폴더만 덮어써도 된다.
> 화면 UI는 미리 빌드해 배포본에 담겨 있으므로 Node.js는 필요 없다.

걱정되면 2번 전에 `vault` 폴더만 다른 곳에 복사해 두면 완전한 백업이 된다.

## 개발

```bash
.venv/bin/python -m pytest backend/tests -q     # 백엔드 테스트
node tests/ui/screens.mjs                       # 화면 테스트 (playwright 필요)
cd frontend && npm run dev                      # UI 개발 서버 (API는 8000번으로 프록시)
```

### 배포본 만들기

```bash
cd frontend && npm run build && cd ..     # 화면을 먼저 빌드한다
python tools/make_dist.py                 # dist/느린나이테-<날짜>-v<판>.zip (파이썬 3.14 · win_amd64)
python tools/make_dist.py --python 3.13   # 사내 PC 의 파이썬이 다를 때
python tools/make_dist.py --no-vendor     # 인터넷이 되는 PC 용 (용량이 작다)
```

이름의 판 번호는 **그날 이미 만든 것 다음 번호**로 붙는다 — 같은 날 다시 만들어도
앞의 배포본을 덮지 않는다.

담기는 파일은 **git 이 추적하는 것**으로 정해진다(`git archive`). 그래서 `vault`·`.venv`·
`__pycache__` 가 딸려 갈 일이 없고, **커밋하지 않은 변경은 담기지 않는다.**
`vendor/` 는 이 명령을 실행하는 PC 에서 PyPI 로 내려받으므로 **빌드하는 쪽은 인터넷이 필요하다.**

**화면 테스트**는 주요 화면이 오류 없이 열리는지, 누른 결과가 약속과 맞는지
(대시보드의 수 = 목록이 거른 수), 그리고 **선택·마우스올림 상태까지 글자가 읽히는지**
(WCAG AA 명암비)를 본다. 화면을 픽셀 단위로 굳히지는 않는다 — 그러면 색 하나 바꿀 때마다
깨져서 아무도 안 돌리게 된다. 배포용 파일(`frontend/dist`)을 그대로 쓰므로
`npm run build` 를 먼저 해야 바뀐 화면이 시험된다.
