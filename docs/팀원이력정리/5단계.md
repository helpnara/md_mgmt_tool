## 3. 업무 이력 파일 — 원본 스펙 2절을 이 도구에 맞춰

```markdown
---
format: slow-way-career-context        ← 원본 형식 이름 그대로(형식의 주인은 원본 — README 6절)
version: 0.2
exported_at: 2026-11-20
owner: 김민준                          ← 익명화면 "익명"
scope: 전체 | 기간 2025-01~2026-12 | 선택 6건
status_included: 확정 | 확정+구조화
anonymized: false
experience_count: 6
app: 느린나이테-20261120-v1
---

# 사용 안내 (AI에게)            ← 원본 2.2 그대로(근거 ID 를 끄면 그 문장만 뺀다)
# 프로필                        ← 이름 · 팀 · 맡은 과제 수(주관 n) · 기간 · 특허 · 수상(증빙에서)
# 과제 (표)                     ← 포함 경험이 있는 과제만: 번호 · 과제명 · 담당 기간 · 역할
# 경험 (최근 것부터)
## [E-012] 출하 검사 판정 기준 정리
- 기간: 2026-03 ~ 2026-09 · 과제: 2026-003 · 역할: … · 구분: 업무 · 상태: 확정
- 도구: Python, SQL             ← 261 ①
### 상황 / 목표 / 행동 / 결과(정량 · 정성 · 영향) / 역량 / 교훈 / 증빙 / 확인 필요(구조화 포함일 때만)
# 역량 색인 (표: 축 | 역량 | 관련 경험)          ← 사전의 대표 이름으로 — 사전에 없는 태그도 넣되 표 아래 한 줄로 따로
# 기술 · 도구 (표: 도구 | 관련 경험)             ← 261 — 원본에 없는 절, v0.3 후보로 원본에 알린다
# 정량 성과 목록 (표: 지표 | 값 | 비교 기준 | 시점 | 경험)
```

* 원본 07 의 직렬화 규칙 그대로 — 빈 칸 줄은 빼고(역할 · 구분 · 상태는 늘), 기간 `YYYY-MM ~ 현재`, 같은 시작 월은 번호 순, **같은 데이터 · 같은 옵션 = 같은 파일**(내보낸 때 빼고).
* 원본의 "소속 표" 는 지금 회사 한 줄뿐이라 프로필에 녹인다(입사 전 소속이 생기면 표로).
* **효과 금액**(2단계에서 정량 한 줄 "과제 전체 금액(본인 몫 아님)") — 정할 것 ③.
* 크기 — 10만 자 넘으면 경고, 30만 자 넘으면 기간으로 나누라는 안내(원본 4.4).
* 파일 이름 — `업무이력_<이름 또는 익명>_<범위>_<YYYYMMDD>.md`(원본 4.5 를 우리 말로).

## 4. 익명화 (원본 07 5절)

* **치환표** — 설정 `anonymize_rules`(팀 하나에 하나): `[{kind, from, to}]` + 정규식 몇(특허 등록번호 `10-\d{7}` 기본). 종류 — 회사 · 조직 · 인명 · 제품 · 공정 · 고객 · 기관 · 기타.
* **후보 자동 추출** — 이 도구는 원본보다 많이 안다: **명부의 다른 사람 이름**(→ "동료 A" …) · 과제의 유관부서 · 과제명 · 증빙의 회사 · 기관명 꼴. 체크 목록으로 보이고 사람이 고른다.
  "고객사 이름 · 공정명은 자동으로 다 찾지 못합니다 — 직접 넣으세요" 고정 문구.
* **적용** — 만든 최종 글에, `from` 이 긴 것부터, 부분 문자열(조사가 붙어도), 영문은 단어 경계, 근거 ID(`E-nnn`) · 과제 번호는 보호. owner 는 "익명".
* **잔존 검사** — 바꾼 뒤 모든 `from` 을 다시 찾아 남으면 경고 · 위치. 후보 중 치환표에 없는 것이 남아 있으면 "치환하지 않은 후보 n개". 경고가 있어도 막지 않는다.

## 6. 팀원 보완 (README ③)

* 팀원 PC 의 사람별 이력(자기 것)에서 경험 상세가 **고칠 수 있게** 열린다 — 단 **초안 · 구조화만**(확정은 보기만).
  확인 필요 [반영] · [해당 없음] · 본문 칸 · 도구 · 역량 태그. 상태 · 확정 · 정합성 [확인함] · 지우기 · AI 로 정리는 팀장만.
* 팀원이 고친 경험에는 **"팀원이 고침"** 표시(233 의 "팀원이 고친 것" 과 같은 결) — 팀장이 확정 전에 볼 수 있게. `edited_by_member_at` 을 남긴다.
* 팀원 PC 도 자기 업무 이력 파일을 내보낼 수 있다(정할 것 ⑥).
