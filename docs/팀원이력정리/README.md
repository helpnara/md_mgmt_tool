## 1. 목표

**느린 나이테에서 과제 수행 이력을 관리하고, 그것을 잘 정리해 팀원별로 역량 · 과제 수행 이력을 정리한다.**
느린 길은 따로 된 앱이 아니라 **느린 나이테 안의 한 영역**으로 들어온다(하나의 통합 시스템).

| 정한 것 | 내용 |
|---|---|
| 쓰는 사람 | **팀장**이 팀원 전체를 정리한다. 팀원은 자기 것을 보고 보완한다(233 의 팀원 PC) |
| 결과물 용도 | **사내**(평가 · 역량 관리)는 시스템 안에서 끝낸다. **개인 업무 이력 · 성과 정리**는 팀원별 **업무 이력 파일**로 건네고, 그 파일로 무엇을 만들지는 본인이 정한다. 그런 용도의 프롬프트는 시스템 안에 두지 않는다(238 ④) |
| 개발 방식 | 느린 나이테를 **업그레이드**한다. 별도 앱을 만든 뒤 합치는 길은 버렸다(골격 · 안전망 · 배포를 두 번 만들고 합치는 일이 더 붙는다) |
| AI | 지금처럼 **부르지 않는다.** 프롬프트를 보여 주고 복사하게 한다(71). 느린 길이 더하는 것은 **응답을 되받아 읽는 것**이다. 사내 AI 가 생기면 113 과 함께 본다 |

## 2. 이미 있는 것과 더할 것

| 이미 있다 | 더한다 |
|---|---|
| 과제 · 진행일지 · 보고 · 담당과 역할(역할 · 맡은 부분 · 담당 기간 · 회고 · 그 밖의 성과 · 기술 · 도구 · 중간 성과) · `★성과` 일지 · 팀원역량(교육 · 행사) · 사람별 이력 · 나의 한 해 · STAR 정리 프롬프트(복사까지) | **경험** 단위: 과제 하나에서 경험 여럿, 상황 · 목표 · 행동 · 결과 · 교훈 · 확인 필요 ([데이터모델](데이터모델.md)) |
| | **응답 되받기**: STAR 프롬프트의 AI 응답을 붙여 넣으면 읽어서 경험에 채운다 ([응답형식](응답형식.md)) |
| | **역량 태그**: 축 넷(기술 · 업무 · 리더십 · 문제해결)과 사전 |
| | **정합성 검사 · 확정**: 초안 → 구조화 → 확정 |
| | **팀원별 업무 이력 파일** 내보내기 · 익명화 |

## 3. 용어 대응

느린 길 설계 문서의 낱말 중 일부는 이 저장소의 금칙어 시험(`test_terms.py`)에 걸린다. 옮길 때는 아래처럼 바꾼다.

| 느린 길 설계 | 여기서 쓰는 말 | 비고 |
|---|---|---|
| Career (소속 회사 · 조직 · 직위 · 기간의 한 줄) | **소속** | 지금 회사는 명부로 충분하다. 입사 전 소속만 따로 적는다 |
| 기존 문서를 경험으로 나누기 | **문서 분해** | 입사 전 이력 문서를 경험으로. 2단계 이후(정할 것 ④) |
| 컨텍스트 파일 | **업무 이력 파일** | 팀원별 내보내기 결과 |
| Project · 과제 | 과제 | 같은 뜻이다. 느린 나이테 과제 번호를 그대로 쓴다 |
| Experience · 경험 | 경험 | 새 개념. `E-nnn` |
| Skill · 역량 | **역량 태그** | 이 저장소의 **팀원역량**(교육 · 행사 기록)과 다른 것이다. 섞이지 않게 "역량 태그"로 부른다(정할 것 ①) |
| STAR 의 T | 목표 | "과제"와 겹치지 않게 |
