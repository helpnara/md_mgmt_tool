> 작성일: 2026-11-09 · 상태: 설계(구현 전) · TODO 253
> 원본: 느린 길 데이터 모델 v0.1(설계 원본 저장소 `docs/04_DATA_MODEL.md`)을 느린 나이테의 사람 · 과제 · 담당 구조에 맞춘 판
> 바뀐 것: 사람 축이 생겼고, 과제는 느린 나이테 과제를 그대로 쓰고, 기록은 진행일지 · 회고가 맡는다

## 1. 계층

```text
사람 (명부 · people/<이름>/)
 ├─ 소속 (입사 전만, 선택)
 └─ 경험 E-nnn
      ├─ 과제 — 느린 나이테 과제 번호, 또는 입사 전 과제(글로만)
      ├─ 재료 — 진행일지 · 회고 · AI 응답 원문 (가리킬 뿐 고치지 않는다)
      ├─ 정량 성과 0..n (지표 · 값 · 기준 · 시점)
      ├─ 증빙 0..n
      ├─ 역량 태그 0..n (축 넷)
      └─ 관련 경험 0..n
```

- 경험은 **사람 한 명**에 속한다. 한 과제를 셋이 맡았으면 경험도 사람마다 따로다(팀원역량 기록이 사람마다 한 장인 것과 같은 이유 — TODO 74).
- 과제 하나에서 경험이 여럿 나올 수 있다(긴 과제의 단계마다, 또는 맡은 부분이 바뀔 때).
- 과제 없는 경험도 있다(과제 밖의 개선 · 교육 운영 등).

## 3. 정량 성과 · 증빙 · 역량 태그

**정량 성과** — 지표 · 값 · 기준 · 시점 네 칸. 값은 글로 둔다(숫자로 읽지 않는다).
`baseline_kind` = `비교`(기존 방식 대비) · `집계`(누적 · 연간) · `조건`(가정) · `미확인`. **비교일 때만** 내보낸 글에 "개선 · 단축 · 증가"를 쓸 수 있다. 기준이 없으면 글자 그대로 `기준 없음`.
효과 **금액은 넣지 않는다** — 복사 · STAR 프롬프트의 지금 규칙과 같다(기대 · 실증이 섞이기 쉽다).

**증빙** — `type`(특허 · 수상 · 발표 · 문서 · 링크) · `text` · `year` · `file`. 같은 증빙이 경험 둘에 붙을 수 있다.

**역량 태그** — 축 넷(기술 · 업무 · 리더십 · 문제해결) 아래 이름. 사전은 설정에 두고(정할 것 ⑤) 대표 이름 + 다른 이름(동의어)으로 응답의 표기를 맞춘다. 첫 사전은 설계 원본 `04_DATA_MODEL.md` 9절의 50개에서 시작한다.

## 4. 상태와 확정

```text
초안 ──(응답 되받기 · 저장)──▶ 구조화 ──(팀장 확정)──▶ 확정
 ▲                                  │                    │
 └────────────(되돌림)──────────────┴────────────────────┘
```

| 상태 | 뜻 | 들어오는 길 |
|---|---|---|
| 초안 | 담당과 역할에서 옮겨 온 것, 쓰다 만 것 | 담당 · 직접 · 읽기 실패 |
| 구조화 | AI 응답을 읽어 채웠고 아직 검토 전 | 응답 · 분해 |
| 확정 | 팀장이 검토해 사실로 인정 | [확정] |

**확정 조건** (모두 맞아야 단추가 열린다)
1. 제목 · 사람 · 역할 · 구분이 있다.
2. 상황 · 행동 · (정량 또는 정성 결과) 중 둘 이상이 있다.
3. 확인 필요가 비어 있다.
4. 정량 성과 중 `미확인`이 없다.
5. 정합성 경고가 없거나, 경고마다 "확인함"으로 넘겼다.

업무 이력 파일에는 **확정만** 기본으로 들어간다.

## 5. 파일

```text
vault/people/<이름>/
├── activities/   (있음 — 팀원역량)
├── meetings/     (있음 — 면담)
└── experiences/  (새로)
    ├── E-001.md
    └── responses/2026-11-20-01.md   AI 응답 원문 — 고치지 않는다
```


(예시의 사람 · 과제 · 수치는 지어낸 것이다.)

- 머리 정보에는 짧은 값만, 긴 글은 본문 절에 둔다. 절 제목은 고정(상황 · 목표 · 행동 · 결과 · 교훈 · 확인 필요).
- 색인은 새 표 `experience`(+ 정량 · 역량 태그 표)로. 스키마 버전을 하나 올린다(추가만).
- 면담과 같은 결 — **검색 · 과제 내보내기에는 넣지 않는다.** 사람별 이력과 업무 이력 파일에서만 보인다. 누가 볼 수 있는지는 정할 것 ③과 함께.

## 6. 담당과 역할에서 초안 만들기 (2단계)

| 담당과 역할 · 과제 | 경험 |
|---|---|
| 과제 번호 · 과제명 | project · title(처음 값) |
| 담당 기간 | start · end |
| 역할 · 맡은 부분 | role |
| 과제 개요의 배경 · 목표 | situation · goal |
| 회고 "내가 한 일" | actions (줄마다 하나) |
| 회고 "결과" · 그 밖의 성과 · 중간 성과 | result_qual (숫자는 정량 후보 → 확인 필요 "기준이 무엇인가") |
| 기술 · 도구 | skills (축 = 기술) |
| `★성과` 일지 | materials |
| 효과 금액 · 다른 사람 이름 · 면담 | 가져오지 않는다 |

초안은 `source: 담당`, 상태 `초안`. 그 뒤 STAR 정리 프롬프트 → 응답 되받기로 `구조화`가 된다.
