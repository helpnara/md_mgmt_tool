## 2. 저장

```text
vault/people/<이름>/experiences/E-001.md      ← 파일 이름 = 번호(바뀌지 않는다)
vault/people/<이름>/experiences/responses/    ← 3단계(응답 원문). 2단계는 만들지 않는다
```

* 머리 정보는 [데이터모델 5절](데이터모델.md) 그대로(짧은 값), 본문은 고정 절 여섯(상황 · 목표 · 행동 · 결과 · 교훈 · 확인 필요).
* **번호** — `E-001` 부터 데이터 폴더 전체에 하나의 줄. 다음 번호 = 모든 사람의 `experiences/E-*.md` + **보관함의 이름**까지 본 가장 큰 수 + 1(접수 번호와 같은 규칙 — 지운 번호를 다시 쓰지 않는다).
* 저장 전 검사는 1단계 `check(…, status)` 를 그대로 쓴다(같은 규칙이 두 곳에 생기지 않게).
* `created_at` · `updated_at` · `created_by` 는 첫 저장부터(소급 불가 — LESSONS 5).

## 3. 색인 (스키마 22 → 23, 추가만)

| 표 | 칸 |
|---|---|
| `experience` | id(`E-nnn`) · person · rel_path · title · project_id · project_text · start · end · role · kind · status · situation · goal · actions(JSON) · result_qual · impact · lesson · lesson_source · open_questions(JSON) · open_count · source · created_at · updated_at · created_by · file_mtime |
| `experience_quant` | experience_id · 순서 · metric · value · baseline · baseline_kind · when |
| `experience_skill` | experience_id · axis · name |

FTS(통합 검색) 색인에는 넣지 않는다. 다시 읽기 · 시작할 때 색인이 사람 폴더를 훑는다(면담과 같은 자리).

## 4. 끝점

| 방법 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/experiences?person=` | 그 사람의 경험 목록(번호 · 제목 · 기간 · 과제 · 상태 · 확인 필요 수 · 경고 수 · 고친 날) |
| GET | `/api/experiences/{id}` | 상세 + 검사 결과(1단계 `check`) |
| POST | `/api/experiences` | 새 경험(초안) |
| PATCH | `/api/experiences/{id}` | 고치기(먼저 고친 사람 알림 — `base_updated_at`, 233 과 같게) |
| DELETE | `/api/experiences/{id}` | 보관함으로 |
| POST | `/api/experiences/draft` | `{project_id, person}` — 담당과 역할 · 회고에서 초안 |

## 5. 담당과 역할에서 초안 (데이터모델 6절)

| 가져오는 것 | 경험 칸 |
|---|---|
| 과제 번호 · 과제명 | project · title(처음 값) |
| 담당 기간(없으면 과제 시작 ~ 끝) | start · end (`YYYY-MM`) |
| 역할 · 맡은 부분 | role — "주관 · 판정 기준 정리" 꼴 |
| 과제 개요의 배경 · 목표 절 | situation · goal |
| 회고 "내가 한 일" | actions — 줄마다 하나 |
| 회고 "결과" · 그 밖의 성과 · 중간 성과 | result_qual. **숫자가 들어 있으면** 정량으로 옮기지 않고 확인 필요에 "‘…’ 의 비교 기준은 무엇인가요?" |
| 기술 · 도구 | skills(축 = 기술) |
| `★성과` 진행일지 | materials(경로만) |
| 효과 금액 · 다른 사람 이름 · 인정 한 줄 · 면담 | **가져오지 않는다** |

`source: 담당` · 상태 `초안`. 그 과제 · 그 사람의 경험이 이미 있으면 새로 만들지 않고 알린다(한 과제에서 경험을 여럿 만드는 것은 [+ 새 경험]으로).

## 6. 화면

**사람별 이력**(`#/person/<이름>`)에 [경험 n건] 카드 — 원본 S-04 를 줄여 옮김:

```text
[경험 6건]   확정 0 · 구조화 0 · 초안 6        [+ 새 경험] [회고 있는 과제 모두 초안]
번호   제목                         기간              과제        상태   질문  고친 날
E-012  출하 검사 판정 기준 정리       2026-03 ~ 2026-09  2026-003   초안    2    11-10
```
맡은 과제 줄에는 그 과제의 경험이 없을 때 [경험 초안] 단추.

**경험 상세**(`#/experience/E-012`) — 원본 S-05 를 2단계 몫만:

```text
← 김민준의 이력                                              [이전 버전] [지우기]
E-012  출하 검사 판정 기준 정리                                초안
┌ 확인 필요 2 ─ (질문 · [지우기])  ──────────────────────────────────────────┐
본문(제목 · 과제 · 기간 · 구분 · 역할 · 상황 · 목표 · 행동 · 결과 정량 표(지표 · 값 · 기준 · 종류 · 시점) · 정성 · 영향 · 교훈 · 출처)
곁가지(역량 태그 — 글자 그대로 · 증빙 · 재료(★성과 일지 링크) · 만든 때 · 고친 때)          [저장]
```

[확정하기] · 정합성 경고 칸은 4단계, AI 응답 붙여넣기는 3단계에 붙는다(자리만 비워 둔다).

## 7. 정할 것

| # | 무엇 | 추천 |
|---|---|---|
| ① | 경험 화면의 자리 | 사람별 이력에 **목록 카드**, 상세는 **따로 주소**(`#/experience/E-012` — 길어서 펼치기로는 좁다) |
| ② | 누가 보나 | 관리자 · 팀장 **모두 보고 고침** / 팀원 PC 는 **자기 것 보기만**(보완은 5단계) / 읽기 전용 공유 바깥은 **막음**(면담처럼 빈 결과) |
| ③ | 2단계의 상태 | **초안만** 만들고 고친다. 구조화는 3단계(응답 되받기), 확정은 4단계(정합성과 함께) |
| ④ | 초안 단추 | 맡은 과제 줄마다 [경험 초안] + 위에 **[회고 있는 과제 모두 초안]**(회고가 빈 과제는 건너뜀) |
| ⑤ | 회고 결과에 숫자 | 정량으로 **자동으로 옮기지 않고** 확인 필요 질문으로(기준 없는 숫자가 성과처럼 굳지 않게) |
| ⑥ | 번호 | `E-001` 부터 데이터 폴더 전체 한 줄, 지운 번호 재사용 안 함(접수와 같은 규칙) |
| ⑦ | 원본과 다른 곳 — 정량 기준을 비울 때의 종류 | 원본 S-05 는 `집계` 가 기본, 1단계 ⑧ 은 `미확인`. **미확인 유지**(확정 전에 사람이 고르게) — 원본에 알린다 |
| ⑧ | 과제가 바뀔 때 | 경험은 **과제 번호로만** 잇는다 — 번호 바꾸기(renumber)를 따라가고, 과제를 지우면 경험은 남고 "지운 과제" 로 보인다 |
| ⑨ | 역량 태그 칸 | 2단계는 **글자 그대로**(축 + 이름). 사전 맞추기는 4단계 |

## 8. 시험 · 크기 · 배포

* 백엔드 — 저장 · 번호(지운 번호 건너뜀) · 고치기 충돌 · 보관함 · 이전 버전 · 색인 다시 만들기 · 이름 바로잡기 · 과제 번호 바꾸기 · 초안 만들기(칸마다 · 숫자 → 질문 · 가져오지 않는 것) · 권한(팀원 자기 것 · 공유 바깥 막음) · 검색에 안 걸림. **40건 안팎**
* 화면 — 목록 카드 · 초안 단추 · 상세 열기 · 고쳐 저장 · 지우기 · 팀원 PC 보기만. **8건 안팎** · 겹침 조사(`overlap.mjs`)에 두 화면 더함
* 코드 — 백엔드 600 · 화면 500줄 안팎
* **화면이 생기므로 배포본 + 체크리스트**를 드린다(255 · 256 과 함께 나가는 첫 배포본)
