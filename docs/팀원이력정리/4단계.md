## 2. 역량 사전

```json
"skill_dictionary": [                     ← settings.json. 비우면(null) 기본 50개
  {"axis": "기술", "name": "비전 AI 객체탐지", "aliases": ["객체탐지", "CNN", "머신비전", "비전 AI"]},
  …
]
```

* **기본값** = 원본 9절의 50개(기술 13 · 업무 13 · 리더십 10 · 문제해결 10 — 표 그대로, 금칙어 시험을 거쳐 옮긴다).
* **이름 맞추기**(원본 FR-C9) — 공백 · 가운뎃점 · 대소문자를 무시하고 대표 이름 또는 동의어와 같으면 **대표 이름 · 사전의 축**으로 바꾼다.
  * 응답 되받기의 저장 · 경험 상세의 저장 · 초안 만들기에서 돈다. 이미 있는 경험은 [사전에 다시 맞추기](사람 하나 단위)로.
  * 못 맞춘 이름은 그대로 두고 **"사전에 없음"** 표시 — 경험 상세의 역량 태그 옆 [사전에 추가] · [기존 역량으로 ▾].
* **편집** — 설정 → [분류] 탭에 "역량 사전" 카드(축 · 대표 이름 · 동의어 · 쓰는 경험 수). 쓰는 경험이 있는 항목은 지우지 않고 **다른 역량으로 합치기**(경험의 태그를 함께 바꾼다).
* **초안의 기술 · 도구**(2단계 — "Python" 같은 도구)는 사전에 없으면 "사전에 없음" 으로 남는다 — 정할 것 ②.

## 3. 정합성 검사 (같은 사람의 경험끼리)

| 코드 | 검사 | 이 도구에서 |
|---|---|---|
| X-02 | 경험 기간이 그 과제의 **담당 기간** 밖 | 담당과 역할의 시작 · 끝(없으면 과제 시작 · 끝)과 월 단위로 비교 |
| X-03 | 행동 · 증빙의 연도가 경험 기간 밖 | 행동 줄의 네 자리 연도 · 증빙의 연도 |
| X-04 | 같은 해 · 같은 종류 증빙인데 이름만 다르다 | 이름 유사 0.6 이상 · 같지는 않음 |
| X-05 | 특허 증빙이 경험 둘 이상에 | 같은 글자의 특허 |
| X-07 | 기간이 비어 연도를 정할 수 없다 | 시작이 빔 |
| X-08 | 중복 후보 — 제목이 비슷하거나 같은 정량 값이 두 경험에 | 1단계 규칙 14 의 "비슷함"(제목 유사 0.8 · 기간 + 정량 값) |
| R-07 | 역할에 본인 몫이 드러나지 않는다 | 3단계의 역할 주체 경고(원본 FR-C10 — 원본은 확정을 막는다) |

* **경고만** — 저장은 막지 않고 확정만 막는다(원본 FR-F1). 상세 위 노란 칸 · [경험] 카드의 "경고" 수에 더한다.
* **[확인함]** — 경고마다. 경험 파일에 `acknowledged: [{code, key, at, by}]` 로 남긴다(FR-F2).
  `key` 는 경고의 내용(상대 경험 번호 · 연도 등)이라 **내용이 바뀌면 다시 묻는다**.
* 계산은 읽을 때(사람 하나 — 수십 건이라 가볍다). 색인 표는 늘리지 않는다.

## 4. 확정

**확정 조건 다섯**(원본 4절 · FR-E6) — 1 ~ 4 는 1단계 `confirm_ready` 그대로, 5 = 3절 경고가 없거나 모두 [확인함].

```text
E-012  출하 검사 판정 기준 정리      구조화   [확정하기 (조건 2개 남음)]  ← 누르면 남은 조건이 펼쳐진다(회색으로만 두지 않는다)
                                    확정     [구조화로 되돌림]
```

* `POST /api/experiences/{id}/confirm` · `/unconfirm` · `/acknowledge`. 확정하면 `confirmed_at` · `confirmed_by`(소급 불가 — 첫 확정부터).
* **확정 뒤에 고치면** 상태는 그대로, 고친 때만 바뀐다(원본 4절). 새 경고가 생기면 상세에 "확정 뒤 생긴 경고" 로 보인다.
* 이어서 저장(3단계)은 확정한 경험에 하지 않는다 — 이미 막혀 있다.

## 5. 확인 필요 — [반영] · [해당 없음] (원본 S-05 · FR-C8)

```text
┌ 확인 필요 2 ─────────────────────────────────────────────────────────────┐
│ 1. ‘재검 월 30건 → 12건’ 의 비교 기준은 무엇인가요?                       │
│    답 [기존 육안 판정 대비____]  반영할 곳 [정량 기준 ▾]  [반영] [해당 없음] │
└─────────────────────────────────────────────────────────────────────────┘
```

* [반영] — 답을 고른 칸 끝에 덧붙이고(정량 기준이면 그 정량의 기준 · 종류 칸) 질문을 지운다. 반영할 곳의 기본은 질문에서 추정(기준 · 역할 · 기간 · 몫 → 정량 · 역할 · 기간 · 결과).
* [해당 없음] — 질문만 지운다. 무엇을 지웠는지는 이전 버전에 남는다.
* 지금처럼 글 칸에서 줄을 지우는 길도 둔다.

## 6. 끝점 (넷 더함 · 설정 키 하나)

| 방법 | 경로 | 하는 일 |
|---|---|---|
| POST | `/api/experiences/{id}/confirm` | 조건 다섯을 서버가 다시 보고 확정(모자라면 400 + 남은 조건) |
| POST | `/api/experiences/{id}/unconfirm` | 구조화로 되돌림 |
| POST | `/api/experiences/{id}/acknowledge` | `{code, key}` — 경고 하나를 [확인함] |
| POST | `/api/experiences/skills/merge` | `{from: {axis, name}, to: {axis, name}}` — 사전 합치기 · 경험 태그를 함께 바꿈 |
| (설정) | `skill_dictionary` | `PUT /api/settings` 로 — 모양 검사(축 넷 · 이름 60자 · 겹침 없음) |

권한 — 확정 · 되돌림 · 확인함 · 사전은 관리자 · 팀장(README ③). 팀원 PC 는 보기만.

## 7. 정할 것

| # | 무엇 | 추천 |
|---|---|---|
| ① | 사전의 자리 | **설정 → [분류] 탭의 "역량 사전" 카드**(README ⑤ — 분류 · 속성처럼 팀장이 고친다). 기본 50개는 원본 9절 그대로 |
| ② | 초안의 기술 · 도구("Python" 등)가 사전에 없을 때 | **"사전에 없음" 으로 두고 확정은 막지 않는다** — 도구는 역량과 결이 달라 사전을 억지로 늘리지 않는다. 필요하면 [사전에 추가] |
| ③ | 사전에 없는 역량 태그가 확정을 막나 | **막지 않는다**(원본 조건 다섯에 없다). 표시만 |
| ④ | 정합성의 범위 | **같은 사람의 경험끼리**. X-01 · X-06 · X-09 는 입사 전 이력을 다룰 때 |
| ⑤ | R-07(역할 주체)을 | **경고로 넣고 [확인함]으로 넘길 수 있게** — 원본은 확정을 막지만, "주관" 처럼 혼자 한 일이 분명한 경우가 있다 |
| ⑥ | 초안에서 바로 확정 | **조건만 맞으면 된다** — AI 를 쓰지 않고 손으로 다 채운 경험도 확정할 수 있게(원본은 구조화 → 확정) |
| ⑦ | 누가 확정하나 | **관리자 · 팀장**. 팀원 PC 는 보기만(보완은 5단계) |
| ⑧ | 확정 뒤 고치기 | 상태 유지 · 고친 때만(원본 4절). 확정 뒤 생긴 경고는 상세에 따로 보임 |
| ⑨ | 확인 필요 [반영] | **4단계에 넣는다** — 조건 3(확인 필요 0)을 채우는 길이 지금은 줄 지우기뿐이라 답이 남지 않는다 |
| ⑩ | 팀 전체 역량 색인(원본 S-07) | **뒤로** — 확정 경험이 쌓인 뒤, 5단계(업무 이력 파일)와 함께 본다. 4단계는 사람별 이력의 [경험] 카드 위에 그 사람의 역량 태그 칩(축별 · 수)만 |
