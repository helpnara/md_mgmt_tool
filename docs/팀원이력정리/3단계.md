## 2. 경험 정리 프롬프트 — `structure_entry` v0.1.1 을 과제 기록판으로

244 의 STAR 정리 프롬프트는 **사람이 읽는 마크다운**(한 줄 요약 · STAR 표 · 불릿 · 말로 설명)을 받는다. 앱이 다시 읽을 수 없다.
3단계는 같은 기록 묶음으로 **앱이 읽는 블록**을 받는 판을 따로 둔다(244 는 그대로 — 정할 것 ①).

```text
[역할] 당신은 제조 · 데이터 분석 업무를 잘 아는 업무 성과 정리 코치입니다.
아래 [기록]은 사내 과제 관리 도구에 한 사람이 남긴 과제 기록입니다. 경험 블록으로 정리해 주세요.

[규칙]                                     ← 원본 규칙 1 ~ 8 그대로(6 은 "기존 경험 목록" 이 이 사람 것) + 아래 둘
1 기록에 있는 사실만 · 2 열린 질문 · 3 질문 3개 이내 · 4 기준 없는 수치에 개선 · 단축 · 증가 붙이지 않음
5 역량 이름은 아래 목록 우선 · 6 이어짐: E-nnn / E-nnn? / 없음 · 7 교훈은 기록에 있을 때만 · 8 역할에 본인 / 다른 주체 구분
9  과제 하나에서 경험이 여럿이면 블록도 여럿. 블록 하나에 경험 하나.            ← 응답형식 2절 규칙 7
10 사람 이름 · 부서명 · 라인 번호 · 사내 시스템명은 일반화. 금액은 쓰지 않는다.  ← 244 규칙 4

[출력 형식]  ```slow-way … ``` 블록만(원본 그대로 — 형식 0.1, 키 이름 · 목록 · 정량 네 칸)
[역량 목록]  이 사람의 경험에 이미 쓴 역량 태그(축별)  ← 사전은 4단계. 생기면 그것으로 바꾼다
[기존 경험 목록]  이 사람의 경험 최근 20건: 번호 · 제목 · 기간 · 과제
[기록]  244 와 같은 묶음 — "## 과제 1. <과제명> (<과제 번호>)" + 기간 · 배경 · 목표 · 역할 · 맡은 부분 · 기술 · 도구 · 중간 성과 · 성과 후보 일지 · 회고 · 그 밖의 성과
```

* **만드는 곳은 백엔드**(`GET /api/experiences/prompt`) — 형식 · 규칙이 파서와 한 곳에 있고, 시험이 pytest 에서 돈다. 244 의 기록 묶음 코드는 화면에 있으니 같은 칸을 백엔드 `person_history` 로 다시 짠다(줄 모양이 같은지 시험으로 묶는다).
* **넣지 않는 것** — 팀원 이름(“이 사람”), 다른 사람 이름, 효과 금액(정할 것 ⑤), 면담.
* 화면에 **글자 수**를 보인다 — 사내 AI 의 붙여넣기 한도에 걸리는지 실험 2차에서 잰다(8절).

## 3. 저장 — 응답 원문

```text
vault/people/<이름>/experiences/responses/2026-11-12-01.md   ← [읽기] 하는 순간. 고치지 않는다
```

* 머리 정보: `person` · `created_at` · `created_by` · `projects`(프롬프트를 만든 과제) · `blocks`(읽은 블록 수) · `saved`(이 응답에서 저장한 경험 번호, 저장할 때 더함).
* 본문 = 붙여 넣은 글 그대로(파서 규칙 15 · 원본 FR-B3). 같은 날 여러 번이면 `-02` · `-03`.
* 저장한 경험의 `materials` 에 이 경로를 더한다 → 경험 상세의 재료에서 원문을 열어 볼 수 있다.
* 색인 표는 만들지 않는다(목록은 폴더를 바로 읽는다 — 사람 하나에 수십 건). 이름 바로잡기 · 보관함은 경험 폴더와 함께 따라간다.

## 4. 끝점 (넷 더함)

| 방법 | 경로 | 하는 일 |
|---|---|---|
| GET | `/api/experiences/prompt?person=&projects=` | 경험 정리 프롬프트 — `{text, chars, projects, existing}` |
| POST | `/api/experiences/read` | `{person, text, projects}` → 응답 원문 저장 + 미리보기(블록 · 기본 저장 방법 · 과제 추정 · 경고) — **아무 경험도 바꾸지 않는다** |
| POST | `/api/experiences/import` | `{person, response, items: [{index, action: 새로 · 이어서 · 버림, target, project, keep: [칸…]}]}` → 저장. **블록은 서버가 원문을 다시 읽어서**(화면이 보낸 값을 믿지 않는다) |
| GET | `/api/experiences/responses/{person}/{이름}` | 응답 원문 보기(경험 상세의 재료 링크) |

권한은 2단계와 같다 — 관리자 · 팀장만(정할 것 ⑥), 공유 바깥 막음.

## 5. 블록 → 경험 칸

| 블록 키 | 경험 칸 | 비고 |
|---|---|---|
| 제목 · 역할 · 구분 · 상황 · 목표 · 결과_정성 · 비즈니스_영향 · 교훈 | title · role · kind · situation · goal · result_qual · impact · lesson(+ lesson_source) | |
| 기간 | start · end | 1단계 `parse_period`. 못 읽으면 비우고 경고 |
| 행동 · 확인_필요 · 증빙 | actions · open_questions · evidences(종류 `문서`) | |
| 결과_정량 | quants | 기준 종류는 1단계 추정 — 규칙 12 질문은 검사 경고로 |
| 역량_기술 · 업무 · 리더십 · 문제해결 | skills(축 + 이름, 글자 그대로) | 쉼표 · 가운뎃점으로 나눔 |
| 회사 · 조직 · 직위 | affiliation | 지금 회사 경험이면 비어 온다 |
| 이어짐 | 저장 방법의 기본값 | 정할 것 ③ |
| (블록에 없음) 과제 | project | 정할 것 ② |
| 미분류 키 | 버리지 않고 확인 필요에 "AI 가 더 적은 칸: …" | 원본 규칙 6 |

`source: 응답` · 상태 `구조화` · `materials` += 응답 원문.

## 6. 화면 — 원본 S-03 을 사람별 이력에 맞춰

[경험] 카드에 **[AI 로 정리]** 단추 → 따로 주소 `#/experience-import/<이름>`(2단계 ①처럼 — 카드 안에 펼치기엔 넓다).

```text
← 김민준의 이력          ① 과제 고르기 · 프롬프트 복사 → ② 응답 붙여넣기 → ③ 확인 · 저장
┌ ① 프롬프트 ─────────────── 44% ┐ ┌ ③ 미리보기 ──────────────────────── 56% ┐
│ 과제: ☑2026-003 ☑2026-011 ☐…   │ │ 블록 3 · 못 읽은 줄 1 · 중복 후보 0 · 미분류 0 │
│ ┌ 전문(읽기 전용 · 스크롤) ───┐ │ │ ┌ 출하 검사 판정 기준 정리 ────────────┐ │
│ └──────────────────────────┘ │ │ │ 2026-03 ~ 2026-09 · 판정 기준은 본인… │ │
│ ⓘ 고정 문구(S-03 ①)  3,120자   │ │ │ 과제 [2026-003 ▾] · AI 제안: 이어짐 E-012│ │
│                   [전문 복사] ✓ │ │ │ 저장 (●E-012 에 이어서 ○새 경험 ○버림) │ │
├ ② 응답 붙여넣기 ───────────────┤ │ │ 확인 필요 2 · 정량 1 · 역량 3 [펼치기] │ │
│ ┌──────────────────────────┐ │ │ └────────────────────────────────────┘ │
│ └──────────────────────────┘ │ │ ┌ ⚠ 못 읽은 줄 ─ 블록 2 · 14줄 … ───┐ │
│             [더 붙여넣기] [읽기] │ │                [저장 — 2건 (구조화로)] │
└──────────────────────────────┘ └────────────────────────────────────────┘
```

* **①** 과제 고르기(기본: 회고가 있고 아직 `구조화` · `확정` 경험이 없는 과제) → 전문은 고르면 바로 다시 만든다. 복사하면 "복사됨 ✓" · ② 에 커서.
  고정 문구(원본 4절 S-03 ①을 사내에 맞춰): "이 글은 사내 AI 로 갑니다. 고객사 이름 · 대외비는 붙이기 전에 지우거나 바꾸세요."
* **②** [읽기] = 원문 저장 + 미리보기. 블록이 없으면 ③ 자리에 "형식 블록이 없습니다. 프롬프트를 처음부터 끝까지 붙여 넣었는지 확인하세요. 응답 원문은 남았습니다." + 원문 앞부분.
  [더 붙여넣기] — AI 가 나눠 출력했을 때 응답을 이어 붙인다(같은 원문 파일에 덧붙임, 미리보기는 누적).
* **③** 블록 카드 — 제목 · 기간 · 역할 한 줄 · 과제 고르기 · AI 의 이어짐 제안 · 저장 방법 · 개수 · [펼치기](모든 칸 읽기 전용).
  역할이 비었거나 본인 / 다른 주체 구분이 없으면 "⚠ 본인이 한 일과 다른 주체가 한 일을 구분해 주세요"(FR-C10 — 저장은 막지 않는다).
  **이어서**를 고르면 카드가 넓어지며 칸별 비교(정할 것 ④). 저장하면 알림 "경험 n건을 저장했습니다" → 사람별 이력의 [경험] 카드로.
* 좁은 화면(1093px 아래)에서는 두 칸이 위아래로.
* 겹침 조사(`overlap.mjs`)에 이 화면 · 미리보기가 찬 상태를 더한다.

## 8. 실험 2차 — 사내 AI(Teams Copilot) 왕복

1차는 원본의 세 서비스 응답 모양(48블록)을 가상 자료로 재현했다. 2차는 **실제로 쓸 사내 AI** 에서 확인한다 — Teams Copilot 부터.

| 순서 | 누가 | 무엇 |
|---|---|---|
| 1 | 사용자 | 3단계 배포본에서 [AI 로 정리] → 과제 1 · 3 · 5개로 프롬프트를 만들어 **Teams Copilot** 에 붙여 넣는다 |
| 2 | 사용자 | 응답을 [읽기] 에 붙여 넣는다 — 원문은 **사내 서버의 데이터 폴더에만** 남는다 |
| 3 | 사용자 | 미리보기 위의 **[실험 요약 복사]** 를 눌러 여기에 붙인다 — 블록 수 · 펜스 유무 · 못 읽은 줄의 **사유만** · 미분류 키 이름 · 경고 코드 · 프롬프트 글자 수 · 응답 글자 수(값은 담지 않는다 — `experience_probe.py --mask` 와 같은 모양) |
| 4 | 개발 | 새 모양은 **지어낸 자료**로 재현해 시험부터 → 규칙 고침 → [실험기록](실험기록.md) 한 줄 → 원본 v0.3 후보 |

볼 것 — 블록만 내라는 지시를 지키나 · 펜스 · 복사 단추로 깨지는 글자(1차의 인용 표식 · U+FFFC 같은 것) · 규칙 2(열린 질문) · 6(이어짐) · 8(주체 구분) · **붙여넣기 한도**(몇 자에서 잘리나 → 정할 것 ⑧).
`tools/experience_probe.py` 는 파이썬이 있는 PC 에서 응답 파일로 볼 때 계속 쓴다. 화면의 [실험 요약 복사] 가 같은 요약을 낸다.
