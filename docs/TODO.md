## 1. 보고 초안의 기본 내용 — 다 채울지, 비워 둘지

**접수**: 2026-09-02 · **상태**: 결정 대기

**현상**
[보고 초안 만들기]를 누르면 마지막 보고 이후의 진행일지 **본문 전체**가 초안에 붙어 나온다.

**불편한 점**
실제로는 그중 필요한 것만 골라 직접 정리해 쓰고 싶은데, 쓰기 전에 지우는 일부터 해야 한다.

**선택지**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 초안을 **빈 칸**으로 시작 (요약·특이사항·다음 계획 뼈대만) | 바로 쓰기 시작 가능 | 무엇을 보고할지 다시 찾아봐야 함 |
| B | 지금처럼 채우되 **[모든 내용 지우기]** 버튼 추가 | 필요할 때만 지움, 참고용으로도 유용 | 기본은 여전히 긴 초안 |
| C | 기본값을 **설정으로 선택** (빈 칸 / 채움) | 취향대로 | 설정 항목이 하나 늘어남 |

**참고**: B로 가더라도 "진행 내용" 절만 지우고 요약·특이사항·다음 계획 뼈대는 남기는 식으로
부분 삭제를 둘 수도 있다.

**결정 필요**: A / B / C 중 선택 (B로 하면 버튼 위치와 문구도 함께)

**영향 범위**: `backend/app/services/reports.py`의 `_draft_body`, `frontend/src/components/ReportEditor.tsx`

## 2. 같은 과제에 보고를 여러 번 남길 수 없음

**접수**: 2026-09-02 · **상태**: **B안으로 결정** (2026-09-02) · **중요도**: 높음

**현상**
보고 이력이 1건 있는 상태에서 [보고 초안 만들기]를 누르면
`2026-09-08 보고 문서가 이미 있습니다.` 가 뜨고 더 이상 진행되지 않는다.

**원인 (확인함)**
보고 문서를 `reports/<보고일>/report.md` 로 저장하기 때문에 **날짜 하나당 보고 하나**다.
그런데 과제 상세의 [보고 초안 만들기] 버튼은 날짜를 묻지 않고 **항상 그 주 화요일**을
기본값으로 쓴다. 그래서 같은 주에 두 번째 보고를 만들려 하면 막힌다.

| 시도 | 결과 |
|---|---|
| 1회차 초안 생성 | 201 정상 |
| 2회차, 같은 날짜 | **409 막힘** ← 지금 겪는 상황 |
| 2회차, 날짜를 직접 지정(예: 2026-09-15) | 201 정상 |
| 1회차를 확정한 뒤 같은 날짜 | 409 막힘 |

즉 기능 자체는 여러 번 보고를 지원하지만, **버튼이 날짜를 고를 방법을 주지 않는 것**이 문제다.
(보고 대상 후보 화면에는 보고 예정일 입력칸이 있어 그쪽에서는 지정할 수 있다)

**선택지**

| 안 | 내용 | 비고 |
|---|---|---|
| A | [보고 초안 만들기]를 누르면 **보고일을 먼저 묻는다** | 가장 단순하고 의도가 분명함 |
| **B ← 채택** | 같은 날짜면 **자동으로 뒤에 번호를 붙인다** (`reports/2026-09-08-2/`) | 누르면 바로 만들어진다. 하루에 중간·완료 보고를 각각 남기는 경우도 대응 |
| C | A + B 둘 다 | 날짜는 고르되, 같은 날 여러 건도 허용 |

**B안 구현 시 정할 것**
- 폴더명 규칙: `reports/2026-09-08/`, 두 번째부터 `reports/2026-09-08-2/`, `-3/` …
- 같은 날짜에 **아직 작성 중인** 보고가 있으면 새로 만들지, 그것을 열지
  (→ 3번 항목의 피보고자 구분이 들어오면 새로 만드는 쪽이 자연스럽다)
- 보고 문서의 `report_date` 는 폴더명이 아니라 front matter 값을 따른다 (둘 다 같은 날짜)

**함께 볼 것**
- 409 메시지가 다음 행동을 알려 주지 않는다. "이미 있는 보고를 열까요, 새 날짜로 만들까요?" 처럼
  선택지를 주는 편이 낫다.
- 이미 있는 그 날짜의 보고가 **작성 중**이면 새로 만들 것이 아니라 그것을 열어 주는 게 자연스럽다.

**결정 필요**: A / B / C 중 선택

**영향 범위**: `backend/app/services/reports.py`의 `create_draft`,
`frontend/src/components/ProjectDetail.tsx`의 보고 초안 버튼

## 3. 보고 이력 한 줄 표기에 피보고자·완료 시각 넣기

**접수**: 2026-09-02 · **상태**: 형식 확정, 세부 결정 대기

**현상**
보고 이력 목록의 한 줄이 이렇게 보인다.

```
2026-09-08   2026-09-08 보고   확정   진행일지 7건
```

날짜가 두 번 나오고, 정작 **누구에게 보고한 것인지**가 없어서 이력으로서 쓸모가 떨어진다.

**바꿀 형식**

```
2026-09-08  [피보고자 또는 회의체명]  보고 완료(2026-09-08 17:40)
```

* 앞의 `2026-09-08` = 보고일
* `[피보고자 또는 회의체명]` = 누구에게 보고했는지 (예: 팀장, 연구소장, 주간회의체)
* `보고 완료(날짜 시간)` = 확정 시각 (`frozen_at`)

**필요한 것**
설계 때 예약만 해 두고 비워 둔 `audience`(피보고자) 필드를 실제로 쓰게 된다.
보고 문서 front matter에 이미 자리가 있으므로 입력칸과 표시만 붙이면 된다.

**정할 것**

| 항목 | 선택지 |
|---|---|
| 입력 시점 | 초안 만들 때 함께 입력 / 확정할 때 입력 / 아무 때나 편집 |
| 입력 방식 | 자유 입력 + 기존 값 자동완성(그룹·담당자와 동일) / 고정 목록 |
| 미입력일 때 | `(피보고자 미입력)` 로 표시 / 그 자리를 비움 / 확정 시 입력을 요구 |
| 작성 중인 보고 | `2026-09-08  팀장  작성 중` 처럼 뒷부분만 다르게 |

**2번 항목과의 연결**
같은 날짜에 보고를 여러 건 남기게 되면(B안), 목록에서 이 둘을 구분해 주는 것이
바로 피보고자다. 두 항목을 같이 구현하는 편이 낫다.

**영향 범위**: `frontend/src/components/ProjectDetail.tsx`(보고 이력 목록),
`ReportEditor.tsx`(입력칸), `backend/app/api/reports.py`(audience 전달),
`backend/app/services/reports.py`(초안 front matter)
