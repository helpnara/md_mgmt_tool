### ⛔ A. 홈의 [작성 중인 보고] 를 누르면 그 초안이 없는 화면으로 간다

보여 준다 (`api/reports.py` — `open_drafts(conn, report_date)`).

```
홈:        작성 중인 보고 1건  →  [누름]
보고 대상: (확정 대기 카드 없음)  ← "1건이라더니?"
```

홈이 말한 것과 데려간 곳이 다르다 — TODO 91 에서 배너로 겪은 것과 같은 부류다.
고치는 길은 하나다: 카드도 `unfinished_drafts` (날짜 무관, 오래된 것 먼저) 를 보게 한다.
줄마다 보고일을 함께 적어 어느 주 것인지 보이게 하면 된다. **반나절 이내.**

## 2. 소급이 안 되는 것 — 순서와 무관하게 먼저

*향후계획 1순위* 의 기준을 그대로 쓴다: **나중에 넣으면 그 전 데이터가 빈칸으로 남는가.**
둘이 걸렸다. 둘 다 반나절이고, 둘 다 지금 쌓이는 과제에 그대로 새겨진다.

### A. 완료일 (`completed_at`)

지금 **과제가 언제 끝났는지 아무 데도 남지 않는다.** 상태가 `완료` 로 바뀐 순간은
`updated_at` 에 묻히고, 그 뒤 태그 하나만 고쳐도 사라진다.

그래서 홈의 **완료 수는 과제 번호의 연도**로 센다 (DESIGN 5.8 에 그렇게 적혀 있다).
2025 년에 시작해 2026 년에 끝낸 과제는 **2026 년 성과에 잡히지 않는다.** 연말에
"올해 완료한 과제" 를 물으면 지금 화면은 답을 못 한다. 실증효과도 마찬가지다 —
*언제 실증됐나* 가 없다.

```yaml
status: done
completed_at: 2026-09-09   # 상태가 done 이 되는 순간 자동으로. 손으로 고칠 수 있다.
```

넣는 것은 한 줄이다. 홈은 **두 기준을 함께** 보여 주면 된다 (착수 기준 / 완료 기준).
어느 쪽을 "성과" 로 볼지는 사용자가 정할 일이고, 그때 가서 정해도 늦지 않다 —
**날짜만 지금부터 남으면 된다.**

### B. 상태 변경 이력

"이 과제 언제 보류됐지?" "검토중에 몇 달 있었지?" 지금은 `.versions` 를 뒤져야 한다.
진행일지에 한 줄 자동으로 남기는 방식이 이 도구답다:

```
2026-09-09  (상태) 진행중 → 보류  ─ 권경락
```

파일이 원본이라는 원칙에도 맞고, 타임라인에 그대로 보이고, 검색된다.
front matter 에 표로 쌓는 방식보다 이 편이 낫다 — 보고 초안에 "이 기간에 보류됐음" 이
저절로 들어간다. **A 와 같이 하면 반나절.**

## 4. 새 기능 — 없어서 도구 밖에서 하고 있는 일

팀장이 **매주 · 매월 · 연말에 실제로 하는 일** 중 지금 이 도구 밖(엑셀·메일·기억)에서
하고 있는 것을 찾았다. 도구의 목적(이력과 보고)에서 벗어나는 것은 5절로 보냈다.

### A. 보고 뒤에 받은 지시사항 — 다음 보고에 답했는가 ★★★

보고를 하면 **지시나 질문이 돌아온다.** "원가 다시 보고" "협력사 일정 확인". 지금 이것을
적을 자리가 없다 — 확정된 보고는 잠겨 있고, 진행일지에 쓰면 다른 기록에 섞인다.
그리고 **다음 보고 때 그 지시에 답했는지**는 팀장 머릿속에만 있다.

제안: 확정된 보고에 **[보고 결과 · 지시사항]** 칸 하나 (확정 뒤에도 쓸 수 있는 유일한 본문).
거기 적은 것은 ① 그 과제 상세 위쪽에 *답하지 않은 지시 1건* 으로 서고, ② 다음 보고
초안을 만들 때 **자동으로 맨 위에 딸려 들어가며** ("지난 보고 지시사항: …"), ③ 초안에서
"답변함" 을 누르면 닫힌다. 보고 이력 화면에서 *답 안 한 지시* 로 거를 수 있다.
**M (2~3일).** 이 도구가 "이력" 에서 "회의를 이어 가는 도구" 로 한 발 나가는 지점이다.

### B. 과제 목록을 엑셀로 — 지금 걸러진 그대로 ★★★

"과제 현황 표 좀 보내 줘" 를 팀장은 한 달에 몇 번 듣는다. 지금은 화면을 보며 엑셀에
다시 친다. 보고 문서에는 [엑셀 셀로 복사] 가 있는데 **목록에는 없다.**

제안: 과제 목록 · 보고 대상 · 홈의 표 넷(팀원별·속성별·그룹별·연도별)에 **[표 복사]** —
지금 걸러진 줄을 탭 구분으로 클립보드에. 붙여넣으면 엑셀 표가 된다. 나가는 것은
클립보드뿐이다. **S (반나절).**

### C. 이 과제를 바탕으로 새 과제 ★★

"2025년 수명평가 표준화" 다음 해에 "2026년 수명평가 표준화". 해마다 도는 과제,
같은 유관부서와 같은 담당자. 지금은 처음부터 다시 친다.

제안: 상세에 **[이 과제로 새 과제 만들기]** — 제목·속성·그룹·담당자·유관부서·개요 본문을
가져오고, 진행일지·보고·첨부는 가져오지 않는다. 시작일은 비워 두어 번호가 올해로.
새 과제 개요 맨 아래에 *이전 과제: 2025-003* 링크를 자동으로 남긴다. **S.**

### D. 홈 표를 기간으로 — 분기 · 반기 ★★

연도 선택기가 T43(기간별 리포트) 을 겸하고 있지만, **분기 실적 · 상반기 보고**는 연도로
안 된다. 보고 횟수는 보고일이 있어 자를 수 있고, 과제 수·완료는 2-A(완료일) 가 있어야
분기로 자를 수 있다 — **2-A 뒤에** 의미가 생기는 항목이다. **M.**

### E. 도움말 화면 — 후임에게 넘길 때 ★

README 는 저장소에 있고 사용자는 배포본을 받는다. 지금 이 도구를 누군가에게 넘기면
설명할 사람이 필요하다. **주간 보고 흐름 · 화면 지도 · 자주 묻는 것** 세 쪽짜리 [도움말]
메뉴. 이미 README 에 있는 글을 옮기는 일이라 **S.** 다만 다수 팀장 체제 직전에 하는
편이 순서에 맞다.

### F. 진행일지에 '다음 할 일' 을 표시하고 홈이 들고 있기 ★

진행일지 서식에 `## 계획` 이 있다. 거기 쓴 것이 **다음 기록을 쓸 때까지 어디에도 안
보인다.** 마지막 기록의 계획 절만 뽑아 과제 상세 맨 위에 *다음 할 일* 로 세우고,
홈 [이번 주 할 일] 에 *계획이 적힌 과제 N건* 을 두는 정도. 할 일 관리 도구가 되지
않도록 **표시만** 한다 — 체크박스도 마감도 두지 않는다. **S~M.**

### 6.3 정해지면 갈 순서 (향후계획 4절 T32~T35 를 지금 구조에 맞춰 다시 씀)

```
0  결정 ①~④                                   ← 사용자
1  2-A 완료일 · 2-B 상태 이력                    소급 불가. 반나절
2  사용자 개념        settings 의 people 에 "로그인 가능" 표시 · 사번
                      요청마다 "지금 누구인가" 를 정하는 한 곳 (지금은 author 설정값)
3  소유 팀            과제 front matter 에 team 한 줄. 번호의 팀 코드에서 초기값
4  로그인             이름 고르기 + 사번 확인 → 작성자 자동 채움 (설정의 작성자 칸은 사라진다)
5  권한               내 팀만 쓰기. API 한 곳(deps)에서 막는다
6  동시 편집          지금의 mtime 비교에 "누가 열어 두었나" 를 더한다 (잠금이 아니라 안내)
7  서버 배포          run.py --host, 윈도우 서비스 등록 스크립트, 방화벽 안내, HTTPS 는 사내 정책 따라
8  화면               홈 · 목록에 팀 거르기 (팀 코드가 이미 있어 거의 공짜)
```

각 단계가 **혼자서도 배포 가능**하도록 잘랐다 — 2·3 은 1인 체제에서도 해가 없고,
4 를 넣기 전까지는 지금과 똑같이 동작한다. 규모는 1~3 이 하루, 4~6 이 3~4일, 7~8 이 2일.

### 6.4 미리 알아 둘 위험

* **동시 편집은 완전히 막지 않는다.** 파일이 원본인 구조에서 실시간 잠금은 구조와 싸운다
  (향후계획 7절). "누가 열어 두었다" 안내 + 저장 시 충돌 감지(지금의 mtime) 까지가 현실적이다.
* **백업·버전 보관은 서버 쪽 일이 된다.** 지금은 각자 PC 였다. 서버의 백업 폴더가 곧 팀 전체의
  안전망이라 R2 첫날 정해야 한다.
* **오류 기록에 과제 내용을 담지 않는 원칙**은 그대로 간다. 다만 *누가* 는 남기게 된다.
* **성능** — 201건·1,000건에서 실측(TODO T23)했지만 팀장 다섯이면 과제 천 건이다. 색인은
  그 열 배도 버티지만 홈의 집계 몇 개는 다시 재야 한다.
