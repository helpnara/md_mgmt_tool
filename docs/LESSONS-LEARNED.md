**다섯 건쯤 모아 착수 확인을 받고 한 번에** 반영하는 방식으로 옮겼다. 배포본도 묶음마다
한 벌이다(09-24 부터). 한 건씩 고치면 그때마다 시험·빌드·배포가 붙어 **부수 비용이 본 작업보다
커진다.** 급한 결함은 그대로 바로 고친다 — 묶는 것은 개선이지 결함이 아니다.

## 1. 숫자 하나에 규칙 하나 — 세는 곳과 보여 주는 곳

**무슨 일이 있었나.**
대시보드가 "보고 대상 5건" 이라 적고 누르면 9건이 나왔다(82). 배너가 "초안 1건" 이라 이름까지
짚어 놓고 후보 전체 목록으로 보냈다(91). 연도 상자에 과제가 없는 해가 서 있었다(96).
홈이 모든 날짜의 초안을 세면서 데려간 화면은 그날 것만 보여 줬다(103-A).
홈이 오래된 과제를 세 건만 세우고 잘렸다고 말하지 않았다(103-B).
**같은 결함을 여섯 번 고쳤다.** 82 를 고치며 DESIGN 5.8 에 규칙까지 적었는데,
그 뒤로 네 번 더 났다 — 규칙을 적는 것과 코드가 그 규칙을 강제하는 것은 다르다.

**왜 반복됐나.**
숫자를 만드는 함수와 목록을 거르는 함수가 따로 있었고, 새 화면을 만들 때마다
*새 숫자*를 만들었다. 숫자는 쉽게 만들어지고, 링크는 나중에 붙이고, 자르기는 화면에서 한다.
그 셋이 각자 다른 기준을 갖는 순간 어긋난다.

**다음에는.**

- [ ] **숫자를 만드는 함수가 목록을 거르는 함수를 부른다.** `count = len(filter(...))` 가
      아니라 화면이 누를 링크의 조건으로 세어야 한다. 서버가 `{count, href_params}` 를 함께 준다.
- [ ] **자르면 자르기 전 수를 함께 보낸다.** `items[:5]` 를 보냈으면 `total` 도 보낸다. 화면이
      `len(items)` 를 건수로 쓰는 순간 결함이다 — 시험으로 고정한다 (101 에서 그렇게 했다).
- [ ] **말한 것과 데려가는 곳이 같아야 한다.** 이름을 말했으면 그리로 보낸다. 그럴 수 없으면
      이름을 말하지 않는다.
- [ ] **거르기 상자는 실제로 있는 것만 세운다.** 골라도 0건인 항목은 "없는 것" 인지
      "고장" 인지 사용자가 구분할 수 없다. 단, 상태·속성처럼 *고르는 말* 은 고정한다 (96).
- [ ] 첫 시험을 **"모든 숫자 = 그 링크의 목록 길이"** 로 쓴다. 이 도구의
      `test_dashboard.py::test_numbers_match_what_the_list_filters` 가 그 모양이다.

## 2. 한 가지 일은 한 곳에서 — 같은 코드가 둘이면 한쪽만 고쳐진다

**무슨 일이 있었나.**
발췌에서 마크다운 기호를 지웠는데(87) 보고 이력 발췌만 고치고 검색 발췌는 두었다(103-C).
첨부 링크의 기준 경로를 편집기는 맞췄는데 목록 화면은 옛 기준을 썼다(22).
팀 코드 검사를 저장에는 걸고 일괄 변경에는 안 걸었다(59). 홈의 팀원별 표와 속성별 표가
같은 것을 다르게 셌다(75). 개요가 서식 그대로인지 판단하는 코드가 없어서 검색·상세·발췌가
각자 진짜 내용처럼 보여 줬다(106-B).

**왜 반복됐나.**
기능을 하나 만들 때 "이 화면에서 필요한 것" 만 짰다. 두 번째 화면에서 비슷한 것이 필요하면
복사했다. 세 번째 화면부터는 첫 번째 것이 어디 있는지 잊었다.

**다음에는.**

- [ ] **"이것을 하는 함수가 이미 있나" 를 먼저 찾는다.** `grep` 30초가 결함 하루를 아낀다.
- [ ] 텍스트 변환(발췌·평문·슬러그), 경로 계산(`filesBase`), 입력 검사(팀 코드·날짜)는
      **한 파일에 한 함수**로 두고 화면·API 가 그것만 부른다. 이름을 붙여 둔다 — `readable_text`,
      `overview_is_blank`, `validate_team_code`.
- [ ] 같은 표가 두 개면 **같은 부품**(`SliceTable`)을 쓴다. 따로 짜면 언젠가 한쪽만 고쳐진다.
- [ ] 검사는 **들어오는 길 전부**에 건다. 저장·수정·일괄 변경·가져오기 — 한 길만 막으면
      소용이 없다 (59).

## 3. 날짜와 연도 — 기준을 문장으로 먼저 적는다

**무슨 일이 있었나.**
보고 초안이 날짜를 안 보고 "아직 안 담긴 기록 전부" 를 가져가 **첫 보고가 1년치를 삼켰다**(81).
과제 번호의 연도가 착수년도가 아니라 **등록한 날**을 따라갔다(95). 완료일이 아무 데도
남지 않아 "올해 끝낸 과제" 를 못 셌다(104). 홈의 연도 기준이 숫자마다 달랐다 — 과제 수는
번호 연도, 보고 횟수는 보고일 연도(110 에서 화면이 그 사실을 적게 했다).

**왜 반복됐나.**
"연도" 라는 한 단어가 실제로는 넷이었다 — 착수년도·등록년도·보고년도·완료년도. 코드는
`datetime.now().year` 가 편해서 그것을 썼고, 그것이 어느 연도인지 아무도 묻지 않았다.

**다음에는.**

- [ ] 설계 첫 주에 **"이 도구의 시간 기준" 을 표로 적는다.** 항목마다 *어느 날짜 열을 보는가*.
      예: `과제의 연도 = start_date 의 연도(없으면 등록일) · 보고 횟수 = report_date · 완료 = completed_at`.
- [ ] `now()` 를 쓰는 곳마다 **"사용자가 날짜를 줄 수 있는가"** 를 묻는다. 과거 자료를 옮겨
      넣는 날이 반드시 온다 — 그날 `now()` 는 전부 틀린다 (81 · 95 둘 다 그 날 터졌다).
- [ ] 기간을 자르는 것과 양을 세는 것을 구분한다. 초안이 *담는* 기록은 보고일까지 자르고,
      미보고 *분량* 은 자르지 않는다 (81). 한 함수에 `until=` 을 넣고 부르는 쪽이 정한다.
- [ ] 두 기준이 다 뜻이 있으면 **하나로 바꾸지 말고 둘 다 세운다** (104 의 완료 / 그해 끝낸 과제).
      바꾸면 지금까지의 수가 달라지고, 사용자가 어느 쪽이 "성과" 인지 정할 기회를 잃는다.

## 4. 사용자의 PC 는 내 PC 가 아니다

**무슨 일이 있었나.**
`setup.bat` 이 LF 줄바꿈과 UTF-8 한글 때문에 윈도우에서 실행되지 않았다. 팀 코드에
`: * ? " < > |` 가 통과해 **윈도우에서만** 폴더 생성이 실패할 코드였다(59). 1366×768 에
125% 배율(기업 PC 기본값)이면 뷰포트가 **1093px** 인데, 필터 줄이 40px 삐져나가
페이지가 흔들렸다(83). 배포본 `vendor/` 가 파이썬 버전을 타는데 사용자 PC 가 3.14 였다.
엑셀이 열어 둔 파일을 지우면 500 이 났다(8.1). 인터넷이 없는 PC 라 "AI 를 부른다" 는
설계 자체가 성립하지 않았다(71).

**왜 반복됐나.**
개발은 리눅스·넓은 화면·인터넷 있는 곳에서 했다. 사용자 환경을 **문장으로 적어 두지 않아서**
매번 배포한 뒤에 알았다.

**다음에는.**

- [ ] 첫날 **`docs/환경.md` 한 쪽**을 쓴다: OS·파이썬 버전·화면 해상도와 배율·인터넷 여부·
      프록시·설치 권한·파일을 여는 다른 프로그램(엑셀). 모르는 것은 사용자에게 **첫날** 묻는다.
- [ ] 윈도우로 가는 파일은 첫 커밋부터: `.gitattributes` 로 `*.bat` CRLF 고정, 배치 파일은
      순수 ASCII, 한글 출력은 파이썬이 맡는다.
- [ ] 폴더·파일 이름에 들어가는 모든 입력에 **윈도우 금지 문자·끝의 점·260자** 검사.
- [ ] 화면 시험에 **사용자 해상도 한 벌**을 넣고 가로 넘침 0 을 고정한다 (5.14).
- [ ] 파일 삭제·이동은 `PermissionError` 를 잡아 "연 프로그램을 닫으세요" 로 안내한다.
- [ ] SPA 진입점(`index.html`)은 **첫날부터 `Cache-Control: no-cache`.** 묶음은 해시 이름이라
      캐시해도 되지만 진입점이 캐시되면 새 배포본을 덮어써도 옛 화면이 돈다 (117 — 실제로 났다).
      그리고 화면 어딘가에 **지금 실행 중인 배포본 이름**을 적어 둔다. "덮어썼는데 안 바뀐다" 를
      한 줄로 가른다.
- [ ] 오프라인이면 **배포본에 바퀴(wheel)를 동봉**하고 이름이 아니라 정보 파일에 파이썬 버전을
      적는다. 배포 스크립트는 `git archive` 를 쓴다 — 커밋 안 한 것이 딸려 가지 않고, `vault` 도
      안 딸려 간다 (그 대신 **커밋 안 한 변경은 배포본에 없다** 는 것을 알고 있어야 한다).

## 5. 나중에 넣을 수 없는 데이터부터

**무슨 일이 있었나.**
완료일을 안 남겨서 이미 끝난 과제들은 영영 완료일이 없다(104). 상태 변경 이력이 없어
"언제 보류됐지" 에 `.versions` 를 뒤져야 했다(105). 반대로 잘한 것 — 과제 생성자·작성자·
팀 코드 자리·담당자 명부를 **다수 팀장 체제를 시작하기 전에** 넣어 두었다(38).

**왜 놓쳤나.**
"필요해지면 넣지" 는 *기능* 에는 맞는 말이지만 *기록* 에는 틀린 말이다. 기록은 그 순간이
지나면 다시 만들 수 없다.

**다음에는.**

- [ ] 설계 때 항목마다 묻는다 — **"이 값을 6개월 뒤에 넣으면 그 전 자료는 어떻게 되나?"**
      빈칸이 남으면 지금 넣는다. 반나절이면 된다.
- [ ] 후보는 늘 같다: **누가(작성자·생성자) · 언제(생성·수정·완료·상태 변경 시각) · 어디서(팀·소유).**
      화면에 안 보여도 저장은 한다.
- [ ] 상태가 바뀌는 것은 **이력으로** 남긴다. 이 도구는 진행일지에 한 줄을 자동으로 쓰는 방식을
      골랐다 — 파일이 원본이고, 타임라인에 보이고, 보고 초안에 저절로 든다.
- [ ] 스키마 버전을 첫날부터 둔다. 이 도구는 `PRAGMA user_version` 이 다르면 색인을 통째로
      다시 만든다 — **색인이 파생물이라서 가능하다.** 원본이 DB 였으면 마이그레이션이 필요했다.
      업데이트 후 `no column named type` 으로 실행이 막힌 사고(8.2)가 이 장치를 만들게 했다.

## 6. 시험은 있었다. 못 잡는 시험이었다

**무슨 일이 있었나.**
대시보드 칩을 고르면 글자가 흰색이 됐다(25). 시험은 **기본 상태의 대비**만 쟀다.
화면 시험이 같은 화면으로 다시 갈 때 자료를 안 읽어, 서버를 바꾸고도 옛 화면을 보고
통과했다(시험 틀 ①). 마우스가 남아 있어 "기본 상태" 를 잰다면서 마우스올림 색을 쟀다(②).
그리고 133건이 통과하는 상태에서 전수 검토를 하니 결함 여섯이 나왔다(103) —
시험이 보는 것만 통과하고 있었다.

**왜 그랬나.**
시험을 "돌아가는지" 로 썼지 "무엇이 틀리면 실패하는지" 로 쓰지 않았다. 시험이 실제로
실패하는지 확인한 적이 없었다.

**다음에는.**

- [ ] 시험을 쓰면 **일부러 깨뜨려서 실패하는지 본다.** 25 를 고친 뒤 그 CSS 를 되살려
      `1.05 < 4.5` 로 잡히는 것을 확인했다 — 그때부터 시험을 믿을 수 있었다.
- [ ] 화면의 **상태 조합**을 돈다 — 기본·마우스올림·선택·선택+올림. 결함은 조합에서 난다.
- [ ] 화면 시험의 이동 함수(`go()`)는 **화면 이름이 같으면 무조건 다시 읽는다.** 주소에 조건이
      붙는 화면에서 "주소가 같으면" 규칙은 한 번도 안 걸린다.
- [ ] 픽셀 비교는 넣지 않는다. 색 하나 바꿀 때마다 깨지는 시험은 곧 아무도 안 돌리고,
      **안 돌리는 시험은 없는 것과 같다** (5.11).
- [ ] 시험이 통과해도 **분기마다 한 번 실제 자료 모양으로 전수 검토**를 한다 (81~90 · 103).
      "쓰면서 걸린 것" 과 "쓰기 전에 찾아낸 것" 은 다른 결함을 잡는다.
- [ ] 문서 정합성도 시험한다 — 메뉴 이름·안내 문구처럼 바뀌기 쉬운 글자는 시험에 박아 둔다
      (94 에서 메뉴 이름을 바꾸자 시험 [9] 가 잡았다).

## 7. "1인 도구" 라도 동시성은 있다

**무슨 일이 있었나.**
화면을 새로고침하면 API 여럿을 동시에 부르는데 커넥션 하나를 나눠 써서 `bad parameter
or other API misuse` 500 이 가끔 났고, 그때 목록이 "나왔다 안 나왔다" 했다(64).
오류 기록 파일에 동시에 덧붙여 줄이 섞였다.

**왜 놓쳤나.**
사용자가 한 명이라 동시 요청이 없다고 생각했다. 사용자는 한 명이지만 **브라우저는 한 화면에
요청 다섯을 동시에 던진다.**

**다음에는.**

- [ ] 요청마다 커넥션을 따로 연다. SQLite 는 WAL 이면 읽기끼리 안 막힌다.
- [ ] 쓰기는 줄을 세운다 — 1인 도구라 잃는 것이 없다. 재인덱싱처럼 큰 쓰기가 작은 쓰기와
      겹치면 방금 만든 것을 지운다.
- [ ] 파일에 덧붙이는 곳(로그·보관함 기록)에 자물쇠 하나.
- [ ] **재현 시험을 먼저 쓴다.** 64 는 읽기·쓰기를 섞어 410건을 동시에 던져 3건 실패를 재현한
      뒤 고쳤고, 고친 뒤 1,230건 0건으로 확인했다. 재현 없이 고치면 고쳤는지 모른다.
- [ ] 못 불러왔을 때 화면이 **침묵하지 않게** 한다 — "없음" 과 "실패" 는 다른 말이고, [다시 시도]
      가 있어야 한다.

## 8. 작업 환경에서 내 손으로 낸 사고 (AI 와 함께 일할 때)

이 프로젝트는 Claude Code 와 함께 만들었다. 코드가 아니라 **작업 방식**에서 난 사고를 적는다.
다음에도 같은 방식으로 일한다면 이것이 가장 먼저 반복된다.

| 사고 | 원인 | 다음에는 |
|---|---|---|
| `pkill -f "port 8791"` 을 치자 **내 셸이 죽었다** (exit 144) | 명령 문자열 자체가 패턴에 걸린다 | 서버는 `$!` 로 PID 를 받아 `kill $SRV`. 패턴으로 죽일 때는 `grep "[u]vicorn"` 꼴 |
| 시험 두 벌을 동시에 돌려 **가짜 실패** | 같은 포트·같은 vault | 돌리기 전에 남은 서버부터 지운다. 포트는 환경변수로 뺀다 |
| 씨앗 자료를 넣는데 **연결 거부** | 서버가 뜨기 전에 불렀다 | `/api/meta` 가 200 이 될 때까지 기다리는 루프를 늘 앞에 둔다 |
| JSX 안 `placeholder="…\\…"` 가 **역슬래시 두 개**로 그려짐 | JSX 속성 문자열은 이스케이프를 풀지 않는다 | `placeholder={"…"}` |
| `sed` 로 여러 파일을 한 번에 바꿔 **pytest fixture 가 재귀** | 패턴이 의도 밖의 줄에도 맞았다 | 바꾸기 전에 `grep -n` 으로 맞는 줄을 눈으로 본다. 넓은 치환은 파이썬 스크립트로 `assert old in s` |
| 여러 파일을 한 스크립트로 고치다 **중간에 실패** — 앞의 것은 저장되고 뒤는 안 됨 | 클래스가 다른 파일에 있었다 | 스크립트는 파일마다 `assert` 로 자리를 확인하고 나서 쓴다. 실패하면 어디까지 됐는지 `git diff --stat` 로 본다 |
| 검토 문서에 **"자동 저장을 기억 안 한다"** 고 적었는데 코드는 이미 기억하고 있었다 | 화면만 보고 적었다 | 결함이라 적기 전에 코드에서 그 줄을 찾는다. 못 찾으면 "확인 필요" 로 적는다 |
| 문맥이 길어져 **요약된 뒤** 파일 위치·함수 이름을 다시 찾는 데 시간이 갔다 | 한 세션이 열흘 이어졌다 | 큰 작업 단위마다 커밋하고, 커밋 메시지에 *왜* 를 적는다. 다음 세션은 `git log` 만 읽어도 잇는다 |
| `.gitignore` 의 `vault/` 가 소스 폴더 `backend/app/vault` 까지 무시해 **새로 받으면 실행이 안 됨** | 앞 슬래시가 없었다 | 무시 규칙은 `/vault/` 처럼 최상위 기준으로. 첫 배포 전에 **새 폴더에 클론해서 실행**해 본다 |

이 밖에 **좋았던 방식** 셋은 유지한다.

* **작은 묶음으로 커밋하고 곧바로 배포본을 만든다.** 사용자가 그날 써 보고 다음 날 피드백을 줬다.
  1~113 중 절반이 실사용 피드백이다. (09-16 부터는 **다섯 건쯤 묶어** 받고, 09-24 부터는
  배포본도 묶음마다 한 벌이다 — 한 건씩 고치면 시험·빌드·배포가 매번 따라붙는다.)
* **결정을 사용자에게 돌려준다.** T20(git 백업)·71(AI 호출)·104(어느 완료가 성과인가)는
  기술이 아니라 정책 판단이었다. 안을 셋 만들어 고르게 했고, 고른 이유를 TODO 에 남겼다.
* **하지 않기로 한 것도 적는다.** 검토 문서 5절 — 왜 안 했는지가 남아야 다음 검토에서 같은 것을
  다시 꺼내지 않는다.

## 9. 새 웹을 시작하는 첫날 점검표

위 여덟 절을 **첫날 반나절**로 압축한 것이다. 코드를 쓰기 전에 끝낸다.

**환경 (30분)**
- [ ] 사용자 PC: OS · 파이썬/런타임 버전 · 해상도와 배율 · 인터넷/프록시 · 설치 권한 · 함께 쓰는 프로그램
- [ ] 자료가 밖으로 나가면 안 되는가 → 그렇다면 **서버는 127.0.0.1**, 외부 호출 0, 오류 기록에 내용 금지
- [ ] `.gitattributes`(CRLF) · `.gitignore`(최상위 기준) · 새 폴더에 클론해서 실행되는지

**데이터 (1시간)**
- [ ] 무엇이 **원본**이고 무엇이 **파생물**인가. 파생물은 언제든 다시 만들 수 있어야 하고, 버전 번호를 갖는다
- [ ] 소급 불가 항목 — 누가·언제·어디서. 화면에 없어도 저장한다
- [ ] **시간 기준 표** — 연도·기간을 자르는 항목마다 어느 날짜 열을 보는가
- [ ] `now()` 를 쓰는 곳마다 "사용자가 날짜를 줄 수 있는가"
- [ ] 폴더·파일 이름에 들어가는 입력의 검사 함수 하나, 들어오는 길 전부에

**화면 규칙 (30분)**
- [ ] 모든 숫자는 눌리고, 누른 목록의 길이와 같다 — 첫 시험이 이것이다
- [ ] 자르면 `total` 을 함께 보낸다
- [ ] 말한 것과 데려가는 곳이 같다
- [ ] 거르기 상자는 있는 것만 세운다 (고르는 말은 고정)
- [ ] 실패는 침묵하지 않는다 — 원인 한 줄 + [다시 시도]

**시험 (1시간)**
- [ ] 서버 시험: 숫자 = 목록, 동시 요청 섞어 던지기, 경로 탈출(`../`)·깨진 파일 하나
- [ ] 화면 시험: 사용자 해상도에서 가로 넘침 0, 대비는 상태 조합 전부, 이동 함수는 화면 이름으로 다시 읽기
- [ ] 시험을 하나 쓸 때마다 **일부러 깨뜨려 실패를 본다**

**일하는 방식**
- [ ] 기능 하나 = 커밋 하나 = 배포본 하나. 커밋 메시지에 *왜*
- [ ] `grep` 먼저 — 이미 있는 함수를 찾는다
- [ ] 정책 판단은 안을 셋 만들어 사용자가 고른다. 고른 이유와 **안 한 것**도 적는다
- [ ] 분기마다 실제 자료 모양으로 전수 검토
- [ ] 서버는 PID 로 죽인다. 시험 전에 남은 서버부터

## 10. 이 도구가 남긴 재사용 가능한 부품

새 웹에서 그대로 가져다 쓸 만한 것. 파일 이름으로 찾는다.

| 부품 | 어디 | 무엇 |
|---|---|---|
| 스키마 버전 → 색인 재생성 | `backend/app/db.py` | `PRAGMA user_version` 이 다르면 통째로 다시 만든다. 손상된 파일도 |
| 요청별 커넥션 + 쓰기 직렬화 | `backend/app/deps.py` | 64 의 결론 |
| 경로 가두기 | `backend/app/vault/paths.py` | `safe_join`, 슬러그, 윈도우 금지 문자 |
| 이전 버전 보관 · 휴지통 | `backend/app/vault/versions.py` | 저장 전 내용을 남기고 되돌린다 |
| 주소가 화면 상태를 든다 | `frontend/src/nav.ts` | `useAddressBar`, `projectLink`, `back` — 즐겨찾기·뒤로 가기가 공짜 |
| 표 복사(TSV) | `frontend/src/tsv.ts` + `CopyTableButton.tsx` | 걸러진 줄 그대로 엑셀로 |
| 폴더 고르기 | `api/folders.py` + `FolderPicker.tsx` | 브라우저가 경로를 안 주는 문제를 서버 목록으로 |
| 화면 시험 틀 | `tests/ui/screens.mjs` | 서버 띄우기·씨앗·`go()`·대비 측정·가로 넘침 |
| 배포본 만들기 | `tools/make_dist.py` | `git archive` + 바퀴 동봉 + 날짜-판 번호 |
| 설정 항목 검증·저장 | `backend/app/services/settings.py` | JSON 설정에 검증 함수를 붙이는 모양 |
| 아이콘 한 장으로 끝내기 | `frontend/public/favicon.svg` + `tools/make_dist.py` | SVG 하나를 원본으로 두고 PNG 를 떠서 **ICO 헤더를 직접 써서** 묶는다(Pillow 없이). 배포본 맨 위에 `.ico` 를 두고 설치 끝에 바탕화면 바로가기를 만든다 |

이 문서는 프로젝트가 끝나는 날이 아니라 **다음 프로젝트를 시작하는 날** 고친다.
그때 위 표에서 무엇을 가져다 썼고 무엇이 또 틀렸는지 적으면, 그것이 다음 회고다.
