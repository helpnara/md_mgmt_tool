## 3. 누가 고치는 중이면 다른 사람은 읽기 전용 — 잠금 정책 (TODO 318)

> 사용자: *"만약 A라는 사람이 화면의 특정 영역을 수정이라면, "A가 수정중"이라고 표시하고 다른 사람에게는 "000이 수정 중이므로 읽기 모드로만 볼 수 있습니다." 메시지를 띄우고 읽기 전용으로 보여지게 해서 conflict를 막는다고 하는 정책에 대해서 검토해줘."*

### 3.1 지금(v94)

| 층 | 무엇 |
|---|---|
| 알림(317, 이번에 넣음) | 편집기를 열면 15초마다 "고치는 중" — 목록 줄에 ✏️ 연필, 같은 글을 열면 편집기 위에 "○○ 님도 지금 고치고 있습니다" |
| 마지막 안전망(기존) | 저장할 때 **연 뒤 바뀌었으면 409** — "이 글을 연 뒤 ○○ 님이 00:00 에 먼저 고쳤습니다 … [새로 열기]" · 고치기 전 모습은 `.versions` 에 |

알림은 **막지 않는다** — 둘 다 고칠 수 있고, 나중에 저장하는 쪽이 409 를 만난다.

### 3.2 잠금(제안)을 하면

**좋은 점** — 충돌이 아예 생기지 않는다. 409 로 쓴 글을 복사해 다시 합치는 수고가 없다.

**걱정되는 점**

| # | 상황 | 일어나는 일 |
|---|---|---|
| 1 | A 가 편집기를 연 채 **자리를 비움 · 회의 · 퇴근**(창은 열려 있음) | 15초 알림이 계속 가서 **잠금이 풀리지 않는다** — B 는 하루 종일 못 고친다 |
| 2 | A 의 노트북이 **잠자기 · 네트워크 끊김** | 알림이 끊긴 뒤 45초면 풀린다 — 이건 괜찮다 |
| 3 | **팀장이 급히 고쳐야** 하는데 팀원이 잡고 있음 | 팀장도 막힌다 |
| 4 | 같은 사람의 **창 두 개** | 자기 다른 창에 막힌다 |
| 5 | 둘이 **같은 초에** 편집기를 엶 | 서버가 한 번에 한 사람만 주도록 해야 한다(가능) |
| 6 | 서버를 다시 켬 | 잠금은 메모리라 비워진다 — 그 사이 둘 다 열 수 있다(409 가 받침) |

**실제로 겹치는 곳** — 팀원은 **자기 일지 · 자기 담당과 역할 줄만** 고친다(233). 그래서 겹침은 대부분 **과제 개요**(담당자 여럿 + 팀장)와 **팀장 ↔ 팀원이 같은 일지**에서 난다. 과제 전체가 아니라 **글 하나**(일지 하나 · 개요 · 보고 하나 · 요청 내용)만 잠그면 된다.

### 3.3 권하는 안 — "부드러운 잠금"

| | 내용 |
|---|---|
| 먼저 연 사람 | 그대로 고친다. 목록 줄에 "✏️ A 고치는 중" |
| 나중에 연 사람 | [수정]을 누르면 **읽기 모드**로 열리고 "A 님이 고치는 중이라 읽기 모드로 엽니다(n분째)." + **[A 가 끝나면 알림]** · **[그래도 고치기]**(확인 창 — 나중에 저장하면 합쳐야 함) |
| 저절로 풀림 | ① A 가 저장 · 닫기 ② 창이 닫히거나 잠듦(45초) ③ **A 가 10분 동안 아무것도 치지 않으면** — 1번 걱정을 막는다 |
| 팀장 | 팀원이 잡은 잠금도 [그래도 고치기]로 연다(팀원에게는 다음 저장 때 409 로 알림) |
| 안전망 | 409 는 그대로 둔다 |

**딱딱한 잠금**(나중 사람은 절대 못 고침)은 권하지 않는다 — 1 · 3 번이 실제로 일어나면 일이 멈추고, 그것을 풀 사람이 없다.
**크기** — 중간(서버의 잠금 주기 · 10분 입력 없음 판정 · 편집기 다섯 곳의 읽기 모드 · 시험). 정해 주면 다음 판에서.
